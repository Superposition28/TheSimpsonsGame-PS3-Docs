Registered format coverage

Compared with the manifest and implementation on 2026-10-18. These are code paths, not a fresh end-to-end conversion run. See the pipeline guide for dependencies and output behavior.

  • Registered extraction/conversion
  • Partial conversion
  • Research / inventory
  • STR → extracted resourcesOperation 1Container extraction preserves payloads for their own format decoders.
  • TXD → PNGOperation 3Named images support model textures and bitmap-font atlases.
  • Preinstanced → BLEND / GLB / FBXOperation 8Geometry import and optional exports; texture/material associations remain partial.
  • LH2 → CSVOperation 9Registered column export; string IDs and text encoding still need runtime validation under the engine Lua host.
  • INF + PNG → FNTOperation 15Font metrics, glyph rectangles, surviving kerning and atlas references.
  • TOX + LH2 → SRT / VTT / CSVOperation 16Joins timing IDs to four language tables; SS supplies labels. Movie companions match by stem and language.
  • SBK / SNU → WAVOperations 10 / 11Separate bank and stream decode paths. The manifest does not request every SBK subsong.
  • MUS → SNR / SNS → WAV segmentsOperation 12Temporary pairs are decoded and removed; MSB transition logic is not reconstructed.
  • VP6 → OGVOperation 13FFmpeg transcodes media; external subtitle generation is separate.
  • Other extracted resource familiesResearch / inventoryCharacter, physics, scene, effect and audio-control resources have varying research coverage; no dedicated conversion is registered.
