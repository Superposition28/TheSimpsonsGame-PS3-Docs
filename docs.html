Documentation Site Guide

This page describes the structure and maintenance conventions for the static reverse-engineering documentation site.

Site Shell

index.html is the documentation shell. It provides the shared top bar, home page, coverage summary, documentation map, hash navigation, and embedded content pages.

  • Each documented destination is loaded in an iframe with a stable id.
  • Navigation uses URL hashes such as #USRDIR-A1_Audio; CSS displays the iframe whose ID matches the current hash.
  • Subpages contain only their page content. Shared navigation stays in the shell, so it can be updated without editing every document.
  • Pages are static HTML and require no build tooling or server.

Hierarchy and Up Navigation

The document tree follows the normalized game layout. Section containers use data-id, while leaf documents use iframe IDs.

  • PS3_GAME contains USRDIR.
  • USRDIR contains the audio, video, character, frontend, level, and hub pages.
  • FormatAnalysis contains the format notes and their linked format pages.
  • The Up button resolves a section route to its parent data-id container, or a leaf iframe route to its nearest containing section. For example, #USRDIR-A1_Audio resolves upward to #USRDIR.
  • Top-level routes resolve to the empty hash, which returns to the home page.

Content Organization

The site has two complementary documentation segments. EU files are the main reference set; equivalent US content may omit some files.

GameFiles Analysis

The game-file analysis tree mirrors the normalized PS3 game layout. Its pages document specific files and directories in their in-game context.

  • PS3_GAME/USRDIR documents the game-data tree, its level-specific resources, and their purpose in the game.
  • A1_Audio documents .exa.snu dialogue and ambient audio plus .mus containers.
  • A1_Video documents .vp6 video assets.

Format Analysis

PS3_GAME/FormatAnalysis documents file formats themselves: their structure, metadata, observed variants, extraction paths, and known use. Its folder layout follows where each format originates.

  • Formats found directly in the game root are documented in their corresponding FormatAnalysis folders.
  • Most embedded formats originate from extracted .STR archives, so their pages live under FormatAnalysis/STR/imbedded-formats.
  • This keeps container-level .STR notes together with the formats extracted from those containers.

Adding a Page

  1. Create the content-only HTML page in the appropriate directory.
  2. Add an iframe with a unique ID and matching source path to index.html.
  3. Add a matching hash link to the documentation map on the home page.
  4. When the new page belongs under a new branch, wrap the related iframes in a section with a data-id so Up navigation has a parent route.
