Documentation guide

This site is a game and file-format reference usable by independent parsers, viewers, extraction tools and game projects. The PS3 EU full release is the canonical baseline; other releases and platforms add explicitly attributed observations.

Canonical sources and paths

Read source identities and path conventions before adding file references. New extracted paths use PS3-EU-Full-audio_reorg-isRenamed. FullFlattened is an alternate namespace, not an interchangeable root. Preserve the provenance of historical measurements. State the original archive and member where verified; mark missing provenance unresolved.

The naming reference separates source folders, extracted names, internal codes and display names. Supplementary PS3 US, demo and Xbox observations must identify their source and cannot silently redefine the EU baseline.

Two complementary trees

Format analysis

Keep root-level extensions beneath FormatAnalysis. Formats extracted from STR remain beneath STR/imbedded-formats. Follow the same container-origin principle for other embedded resources. Functional topic indexes may cross-link without relocating specifications.

When a variant uses the same extension, add a clearly labeled platform/release section to the existing page. An Xbox-only extension gets its own file in an xbox subfolder at the corresponding location. Similar names do not establish compatible layouts.

Game files and asset/use analysis

USRDIR follows the major resource groups where most game data lives. It documents inventories, characters, levels, audio, movies, resource associations and implementation guidance. Link a concrete asset to its format specification and link specifications back to meaningful examples.

Keep current major folders. Mirror deeper source directories when they carry enough distinct analysis to justify a page; otherwise use relative-path inventories within the nearest useful page. This initial policy leaves the final mirroring depth open. Every page states its dataset and directory scope; a documentation path is not itself a game path.

Format-page contract

  • Purpose and role in the game.
  • Identification, platform/release scope, byte order and encoding.
  • Known layouts, alignment, pointer bases, units and parsing constraints.
  • Related resources with the actual join and its evidence.
  • Examples, unknowns, conflicting interpretations and sample provenance.
  • Optional links to tools and project integrations.

Separate structural knowledge, semantic confidence, sample scope and implementation support. Do not call a format complete because one converter exports it. Source-inspected importer behavior is attributed evidence, not a substitute for validating original bytes or runtime semantics. Illustrative parsers are labeled even when a converter exists elsewhere.

Project-specific material

Remake Engine integration owns operation IDs, dependencies, normalization rules, generated outputs and editor-specific usage. Core pages can cite implementations without making those tools a prerequisite. AudioMap remains in the audio analysis tree using V2; the registry and its consumer share the documented contract.

The PS3 and Xbox 360 homepages are an explicit exception: Pipeline Format Coverage combines format research progress and Remake Engine implementation progress. Keep the older coverage-list and coloured Documentation Map layout on both platforms. Green means usable output or readable source; yellow means partial implementation or validation pending; blue means analysis only; orange means research TODO or inventory only; grey means no verified platform support. These are progress labels, not percentages of complete format understanding.

Static shell and compatibility

index.html is the shared shell. Hash links select lazy iframes. Existing routes and anchors are retained, including the former pipeline URL, which is now a compatibility entry to the integration reference. The Up link uses data-id containers and iframe IDs to find a parent route. Content pages also open directly.

reference/coverage.json owns homepage status labels, evidence notes and platform-specific colours. The tracked counts, coverage lists and map dots are committed HTML generated by python -B tools/render_home.py. Run it after changing the registry; --check detects stale output. The site works directly from a file URL without loading JSON at runtime. Research/source scope links remain below the main coverage and map panels.

Validation and maintenance

Run python -B tools/check_docs.py for standalone validation. Run python -B tools/check_docs.py --module-checks for optional comparisons with operations.toml and script paths in a module checkout. The core checks never require proprietary game data or the parent project.

Sources and naming pages are generated from committed JSON using python -B tools/render_reference.py; --check detects stale output. Use shared CSS, viewport metadata, scrollable tables and collapsed sample appendices. Preserve preformatted research content and attribution. Review changed layouts at desktop and narrow widths.

Adding a page

  1. Choose the format-origin tree or USRDIR asset/use tree.
  2. Declare source and path scope; separate observations from assumptions.
  3. Add the content page and reciprocal relationships where relevant.
  4. Add a unique iframe route and links in the appropriate documentation map. New structural branches get a data-id wrapper for Up navigation.
  5. Run the checker, review the rendered page and preserve old URLs when replacing existing material.
