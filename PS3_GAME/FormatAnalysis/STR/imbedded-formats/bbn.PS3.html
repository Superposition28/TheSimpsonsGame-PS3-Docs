Verified bunny binding tables and model join

Inspected on 2026-10-22: ps3-eu-extracted:L01_LandOfChocolate/loc/Challenge_Mode/Challenge_Mode_Design_str/build/PS3/pal_en/assets/shared/bonebindings/npc_default.bbn.PS3, 1,344 bytes, SHA-256 352360f5a8064ebe129230310beaf811d3e28195450e2420a203a77bcfbd9c82. Its original archive and member, all table entries and joins are recorded in the collision provenance ledger.

One validated npc_default sample; offsets are file-absolute
Offset BE u32 value / layout Meaning
0x18 30 Alias-entry count.
0x1C 29 Rig-entry count.
0x20 0x28 Absolute rig-table offset.
0x24 0x110 Absolute alias-table offset.
0x28 + 8*i {string offset, rig hash} 29 rig entries; bounded NUL-terminated ASCII string at the absolute offset.
0x110 + 16*i {string offset, alias hash, rig index, flags} 30 aliases; rig index is zero-based into the rig table. Flags retained without runtime interpretation.

Every rig-name hash (29/29) and alias hash (30/30) equals lowercase SDBM: start with h = 0, then h = (byte + 65599*h) mod 2^32 for each lowercase ASCII byte. This validates these identifier namespaces in this sample, not all game hashes.

All nine npc_bunny ACS binding IDs at record +0x08 match alias hashes. For example, D3693CBE → “left ankle” → rig index 17 → l_ankle / 842EFC24. That rig hash matches a little-endian node ID in the bunny visual model's HAnim node table. Both inspected LODs contain all 29 BBN rig hashes; BBN index 17 is not itself the model's node index (14 in this example).

Some identifiers in other ACS resources may name rig nodes directly rather than aliases; the bunny's alias route must not be imposed on every file. Bone poses, mesh skinning indices, animation decoding and target-engine coordinate conversion remain separate tasks.

Historical player_default interpretation

The retained role descriptions below are hypotheses inferred from names, not observed runtime uses. The npc_default table layout above has its own explicit sample scope.

Format: BBN — Bone Bindings (PS3 build)

Your player_default.bbn.PS3 is a bone-binding table compiled for PS3. It defines the canonical skeleton joints, their IDs, names, and lookup tables used by animation, IK, and gameplay systems.

Why this fits

  • The filename path: .../assets/shared/bonebindings/player_default.bbn.PS3 → shared skeleton bindings.

  • Clear joint names & aliases in the string block:

    • Short rig names: m_pelvis, m_lumbar, m_thoracic, l_hip, r_knee, l_wrist, r_clav, m_neck2, m_jaw, r_weapon, etc.
    • Friendly labels: right elbow, pelvis, left clavicle, right eyelid top/bottom, etc.

  • Small header with counts/offsets, then a sequence of offset tables followed by the name table.

  • Presence of special tags like AITrajectory and r_eye/l_eye shows extra bindings for look/aim vectors and AI helpers.

What the game uses it for

  • Consistent bone ID ↔ name mapping across characters and tools.
  • Attachment points for props/weapons (r_weapon, hands, head).
  • Animation retarget/IK constraints (knees, hips, wrists, spine chain).
  • Facial/eye controls (r_eye, eyelids, m_jaw) for look-at and lip/eye cues.
  • AI & camera helpers (AITrajectory).
  • Acts as the shared “player” skeleton contract that animation banks (e.g., your .bnk) and controllers (.cec) reference at runtime.
