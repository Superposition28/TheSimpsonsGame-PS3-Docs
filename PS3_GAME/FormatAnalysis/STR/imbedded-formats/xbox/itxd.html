Instanced Texture Dictionary (.itxd)

Version: 1.0
Last Updated: 2026-10-05
Author(s): samarixum

The .itxd (Instanced Texture Dictionary) format is the Xbox 360 counterpart to the PS3 .txd format used in The Simpsons Game. Unlike the PS3 version—which wraps textures in classic RenderWare stream chunks (0x16, 0x01, 0x15, 0x03)—the .itxd format uses a pre-serialized (instanced) memory dump container starting with the signature 75 7A 00 03. It embeds a raw Xbox 360 Xenos GPU D3DBaseTexture descriptor and stores pixel payloads in Xenos tiled layout.

Endianness: Big-Endian (PowerPC native) for integers and descriptors; 16-bit byte-swapped (GPUENDIAN_8IN16) for DXT block payloads.
Character Encoding: ASCII / UTF-8 (null-padded fixed 64-byte field).

Architectural Comparison (.txd vs .itxd)

Feature PS3 .txd (Streamed RenderWare) Xbox 360 .itxd (Instanced / Pre-serialized)
Container Header 12-byte RenderWare chunk 16 00 00 00 + size + 2D 00 02 1C Instanced arena header starting with 75 7A 00 03
Endianness Mixed (LE chunk headers/sizes, BE texture dimensions) Big-Endian (PowerPC native)
EA Plugin Hash (0xEA2F) Stored at EOF inside a trailing 0x03 Extension chunk Stored in the header at offset 0x7E right after the texture name
GPU Descriptor 16-byte RenderWare PS3 metadata block at signature +0x50 52-byte Xbox 360 D3DBaseTexture (Xenos GPU fetch constants) at 0xE4
Pixel Layout Morton (Z-order) swizzled for linear formats; standard DXT Xbox 360 Xenos macro/micro-tiled (padded to 32x32 tile boundaries)
32-bit Channel Order BGRA (e.g., 79 2D 20 00) RGBA / ARGB byte-reversed RGB (e.g., 20 2D 79 00)

Parsing Algorithm Overview

  1. Validate the 4-byte magic signature 75 7A 00 03 at offset 0x00 and the EA plugin ID 00 00 EA 2F at offset 0x08.
  2. Read the texture name from the 64-byte null-padded block starting at offset 0x38.
  3. Read the filter/addressing mode at 0x78 and the 8-byte EA texture GUID/hash at 0x7E.
  4. Read the Big-Endian dimension and payload table between 0xA0 and 0xE3 (Width at 0xAC, Height at 0xB0, BPP at 0xB4, Mip Count at 0xDC, and Payload Size at 0xE0).
  5. Parse the Xbox 360 D3DBaseTexture GPU descriptor at 0xE4–0x117 to confirm the GPUTEXTUREFORMAT (at 0xED) and bitpacked GPUTEXTURESIZE_2D (at 0x104).
  6. Seek to the pixel data payload at offset 0x4B0 (for single-texture dictionaries) and read Payload Size bytes.
  7. Untile the Xenos macro/micro-tiled surface (and perform 16-bit byte-swapping for DXT formats or channel reordering for 32-bit formats).
  8. Export the linear surface to DDS.

File Header & Container Layout

1. Instanced Arena Header (0x00 – 0x37)

Offset Size Type Endian Description
0x00 4 UInt32 BE Instanced container magic signature: 75 7A 00 03 ("uz\x00\x03").
0x04 4 UInt32 BE Version / count field; observed value 00 00 00 01.
0x08 4 UInt32 BE EA Plugin ID: 00 00 EA 2F (0x0000EA2F).
0x0C 4 UInt32 BE Arena flags / header size parameters; observed 00 58 00 20.
0x10 4 UInt32 BE Section count; observed 06 00 00 00.
0x14 12 Bytes - Reserved / zero padding.
0x20 24 UInt32[6] BE Arena section offsets: 0x30, 0x30, 0x00, 0xA0, 0x00, 0x18, 0x18.

2. Texture Identification & EA Hash Block (0x38 – 0x9F)

Offset Size Type Endian Description
0x38 64 Char[64] - Null-padded ASCII texture name (e.g., sparkle or moh_sky_zone1_sky2).
0x78 2 UInt16 BE Filter and UV addressing mode (e.g., 11 02 or 11 06). Matches the filter bytes in the PS3 .txd header.
0x7A 4 UInt32 BE Record flag; observed 00 00 00 01.
0x7E 8 UInt64 Raw 8-byte EA plugin GUID/hash (e.g., 92 69 39 D6 C5 E4 FA 20 for sparkle). Identical to the 8-byte payload inside the trailing 0xEA2F chunk in the PS3 .txd.
0x86 26 Bytes - Zero padding up to offset 0xA0.

3. Dimension & Payload Table (0xA0 – 0xE3)

Offset Size Type Endian Name Description
0xA0 4 UInt32 BE SelfOffset Block start offset (0x000000A0).
0xA4 8 Bytes - Reserved Zero padding.
0xAC 4 UInt32 BE Width Texture width in pixels (e.g., 0x40 = 64, 0x400 = 1024).
0xB0 4 UInt32 BE Height Texture height in pixels (e.g., 0x40 = 64, 0x400 = 1024).
0xB4 4 UInt32 BE Depth / BPP Bits per pixel (0x08 for DXT3/5, 0x04 for DXT1, 0x20 for 32-bit RGBA).
0xB8 8 Bytes - Flags Observed 00 00 00 00 00 04 00 00.
0xC0 4 UInt32 BE FormatHint Observed 0x00000000 in DXT, 0x85000000 in 32-bit uncompressed.
0xC4 4 UInt32 BE Reserved Zero padding.
0xC8 4 UInt32 BE LogicalWidth Repeated texture width in pixels.
0xCC 4 UInt32 BE LogicalHeight Repeated texture height in pixels.
0xD0 4 UInt32 BE Reserved Zero padding.
0xD4 4 UInt32 BE SubHeaderPtr Offset pointer; observed 0x000000F4.
0xD8 4 UInt32 BE StreamFlag Observed 0x00000000 or 0x00010000.
0xDC 4 UInt32 BE MipMapCount Number of mip levels present (e.g., 1 or 6).
0xE0 4 UInt32 BE PayloadSize Total byte size of the pixel data blob starting at 0x4B0 (e.g., 0x1000 for 64x64 DXT, 0x556000 for 1024x1024 RGBA with 6 mips).

4. Xbox 360 D3DBaseTexture Descriptor (0xE4 – 0x117)

This 52-byte region is an embedded Xbox 360 Direct3D 9 D3DBaseTexture header containing the hardware texture fetch constant registers (GPUTEXTURE_FETCH_CONSTANT) for the Xenos GPU.

Offset Size Type Endian Description
0xE4 8 UInt32[2] BE D3DResource common header (0x00000010, 0x00280001 / 0x00182801).
0xEC 2 UInt16 BE Xenos format descriptor. Low byte at 0xED is the native format code (0x02 = DXT1, 0x52/0x02 = DXT3/5, 0x86 = 32-bit 8_8_8_8).
0xF8 24 UInt32[6] BE Xenos GPU 6-DWORD Texture Fetch Constant:
  • DWORD 0 (0xF8): Tiling & pitch configuration.
  • DWORD 1 (0xFC): Base address & GPUTEXTUREFORMAT (low 6 bits: 0x02 = DXT1, 0x14 = DXT4_5, 0x06 = 8_8_8_8; bit 7 = 0x80 tiled flag).
  • DWORD 2 (0x100): GPUTEXTURESIZE_2D bitfield:
    • Bits 0–12: Width - 1 (e.g., 0x03F = 63 → 64px; 0x3FF = 1023 → 1024px).
    • Bits 13–25: Height - 1 (e.g., 0x03F << 13 = 0x7E000 → 64px; 0x3FF << 13 = 0x7FE000 → 1024px).
  • DWORD 3 (0x104): Swizzle/Component mapping (0x0007E03F / 0x007FE3FF depending on alignment).
  • DWORD 4–5 (0x108–0x10F): Mip address, min/max mip level clamping, and border color.
0x118 920 Bytes - Zero padding up to the 4KB-aligned/sector-aligned data start at offset 0x4B0 (1,200 bytes).

Format Codes & Pixel Layout

Header Byte (0xED) Fetch Format (0xFF) Format Name BPP (0xB4) Handling
0x52 / 0x02 0x02 DXT1 4 Swap every 2 bytes (16-bit endian swap), untile Xenos macro-tiles, export as DXT1.
0x53 / 0x02 0x02 / 0x13 DXT3 / DXT5 8 Swap every 2 bytes (16-bit endian swap), untile Xenos macro-tiles, export as DXT3/DXT5.
0x86 0x86 Uncompressed 8_8_8_8 32 Untile Xenos 32x32 macro-tiles. Swap R and B channels if converting to PS3/DDS BGRA.

Xbox 360 Xenos Untiling & Padding

Macro-Tile Padding: The Xbox 360 Xenos GPU organises textures into 32x32 macro-tiles (composed of 8x8 micro-tiles). For DXT block-compressed textures, each 4x4 texel block is treated as a single element, meaning a 32x32 block macro-tile covers 128x128 pixels (4,096 bytes for DXT3/5). Consequently:

  • A 64x64 DXT5 texture (such as sparkle, which only requires 2,048 bytes of linear DXT5 data) is padded to a full 4,096-byte (0x1000) Xenos tile allocation, resulting in large runs of 0x00 padding bytes inside the 0x4B0–0x14AF payload.
  • Mipmap chains in files like zone01_split2.itxd include packed tail mips padded out to tile alignment boundaries, explaining why the 1024x1024 6-mip payload is 0x556000 bytes (5,595,136 bytes) on Xbox 360 compared to 0x555400 bytes (5,592,064 bytes) on PS3.

32-Bit Channel Reversal: Comparing identical pixels between PS3 .txd and Xbox 360 .itxd in zone01_split2 reveals that the RGB channels are reversed while Alpha remains in byte 3:

  • PS3 .txd (BGRA): 79 2D 20 00, 7E 31 22 1C, 83 35 24 00
  • Xbox 360 .itxd (RGBA): 20 2D 79 00, 22 31 7E 1C, 24 35 83 00

Complete Parsing Example (Pseudocode)


function parse_itxd(file_data) {
    // 1. Validate magic and EA plugin ID
    if (read_u32_be(file_data, 0x00) != 0x757A0003) return null
    if (read_u32_be(file_data, 0x08) != 0x0000EA2F) return null

    // 2. Read 64-byte texture name at 0x38
    raw_name = file_data[0x38 : 0x78]
    name = read_ascii_until_null(raw_name)

    // 3. Read filter mode and 8-byte EA hash
    filter_mode = read_u16_be(file_data, 0x78)
    ea_hash = file_data[0x7E : 0x86]

    // 4. Read dimensions and payload info
    width        = read_u32_be(file_data, 0xAC)
    height       = read_u32_be(file_data, 0xB0)
    bpp          = read_u32_be(file_data, 0xB4)
    mip_count    = read_u32_be(file_data, 0xDC)
    payload_size = read_u32_be(file_data, 0xE0)

    // 5. Read Xenos D3DBaseTexture format byte
    xenos_fmt = file_data[0xED]

    // 6. Extract tiled pixel payload starting at 0x4B0
    pixel_data_start = 0x4B0
    raw_payload = file_data[pixel_data_start : pixel_data_start + payload_size]

    // 7. Untile and convert endianness
    if (xenos_fmt == 0x86) {
        // 32-bit RGBA: Untile Xenos 32-bit surface and swap R/B to BGRA for DDS
        linear_data = xenos_untile_32bpp(raw_payload, width, height)
        linear_data = swap_rgba_to_bgra(linear_data)
    } else {
        // Block-compressed DXT: 16-bit byte swap (8IN16) then untile 4x4 blocks
        swapped = byte_swap_16bit(raw_payload)
        linear_data = xenos_untile_dxt(swapped, width, height, bpp)
    }

    return {
        name: name,
        ea_hash: ea_hash,
        width: width,
        height: height,
        bpp: bpp,
        mip_count: mip_count,
        format: xenos_fmt,
        data: linear_data
    }
}
