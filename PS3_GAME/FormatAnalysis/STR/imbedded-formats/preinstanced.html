Game format research · PS3 EU reference baseline

Stores PS3 geometry, submesh descriptors, multiple UV sets, materials, skinning weights, and texture associations in .dff.PS3.preinstanced and .rws.PS3.preinstanced stream resources.

Identification
Criterion RenderWare 3.7.0.2 Clump (rwID_CLUMP = 0x00000010) containing nested RenderWare geometry/material chunks and EA EARS (EA Render Studio) custom extension plugins: 0x0000EA33 (EARS_MESH), 0x0000EA13 (material shader parameters with TLFD signature), and 0x0000EA16 (clump preinstance extension).
Byte order / text
Mixed-Endian: RenderWare stream chunk headers, chunk size words, and EARS_MESH header buffer sizes are Little-Endian (UInt32 LE); CPU submesh metadata (Buffer 1) and GPU vertex/index arrays (Buffer 2) are Big-Endian (UInt32 BE, Float32 BE, UInt16 BE).

Evidence and limitations

The Blender importer (operation 7) converts geometry and can export GLB or FBX. With the 2026-10-31 reverse-engineering discoveries from EBOOT.elf, the buffer partitioning invariant (MeshChunkSize == 12 + HeaderDataSize + GpuDataSize), runtime pointer relocation table (mDataTable), 1-to-1 material index mapping, and standard RenderWare skinning/HAnim nodes are completely verified. Texture/material assignments map directly to RenderWare material list entries rather than relying on empirical heuristic string pairings.

All offsets in the specification tables are zero-based; range ends are exclusive unless stated otherwise. Binary fields are verified against both static executable code and 100% of tested asset samples across GameFiles/.

Bunny collision bindings and HAnim nodes

On 2026-10-22, both bunny_dark LOD3 and LOD5 preinstanced models in ps3-eu-extracted:L01_LandOfChocolate/loc/Challenge_Mode/Challenge_Mode_Design_str/ were checked against the co-contained npc_default BBN tables and npc_bunny ACS. Exact full paths, SHA-256 values, original STR records and node entries are retained in the provenance ledger.

Both samples contain a little-endian RenderWare HAnim chunk (0x11E) at file 0xC8, with its payload at 0xD4. The payload's first five u32 values are {0x100, 0, 100, 0x38002, 0}, interpreted as version, hierarchy ID, node count, flags and keyframe size. The 100-entry node table begins at 0xE8 and uses a 12-byte stride: {node ID, node index, flags}, all little-endian. All 29 BBN rig hashes match HAnim node IDs in each model. The verified chain is ACS record +0x08 → BBN alias hash → BBN rig index → rig hash → HAnim node ID → HAnim node index.

Overview & Engine Architecture

  • Format Name: RenderWare Clump with EA EARS_MESH Extension (Simpsons Game Preinstanced Asset)
  • Common File Extension(s): .dff.PS3.preinstanced (2,034 files), .rws.PS3.preinstanced (3,499 files)
  • Purpose/Domain: Defines complete 3D model geometry, submeshes, materials, texture name associations, skeletal hierarchies, and GPU vertex/index streams for assets in The Simpsons Game (PS3).
  • Originating System: Criterion RenderWare Graphics 3.7.0.2 (library ID 0x1C02002D) customized by EA Redwood Shores / Black Box with the proprietary EARS (EA Render Studio) runtime architecture.
  • Format Type: Hierarchical binary RenderWare stream (starts with rwID_CLUMP = 0x00000010).
  • Endianness: Mixed-Endian:
    • RenderWare standard 12-byte chunk headers, chunk size words, and EARS_MESH stream size fields are Little-Endian.
    • EARS_MESH internal metadata (Buffer 1), relocation tables, submesh records, and GPU vertex/index streams (Buffer 2) are Big-Endian.
  • General Buffer Structure: The primary geometry chunk (0x0000EA33) is partitioned into two contiguous buffers:
    • Buffer 1 (CPU Metadata): Starts at chunk relative +0x0C (file +0x18). Size is declared by HeaderDataSize (previously misnamed FaceDataOff). Contains bounding volumes, relocation fixup table (mDataTable), submesh table, and vertex/face descriptor blocks.
    • Buffer 2 (GPU Vertex & Index Streams): Starts immediately after Buffer 1 at +0x18 + HeaderDataSize. Size is declared by GpuDataSize (previously MeshDataSize). Contains raw vertex attributes and triangle-strip index buffers.

Texture Name & Material Association

In standard RenderWare rwID_TEXTURE (0x06), every texture node contains two sequential string chunks:

  1. Diffuse Texture Name: rwID_STRING holding the primary color map filename (e.g. slingshot_ammo, bart_body).
  2. Alpha/Mask Texture Name: rwID_STRING holding the alpha/mask map filename (almost always an empty string "" with null or 0xBF padding).

Because materials are ordered sequentially in rwID_MATLIST, the $N$-th material (0-indexed) corresponds to string chunk index $2N$ (with its mask at $2N+1$). Each submesh header in Buffer 1 declares a 0-based MaterialId field, which maps 1-to-1 to the material index in rwID_MATLIST:


Submesh[i].MaterialId == 0  -->  Material[0]  -->  Diffuse String [0]
Submesh[i].MaterialId == 1  -->  Material[1]  -->  Diffuse String [2]
Submesh[i].MaterialId == 2  -->  Material[2]  -->  Diffuse String [4]

This formally verifies the base_string_index = material_id * 2 relationship observed empirically in the Blender addon.

Mesh Chunk Header Structure (EARS_MESH)

The EA_EARS_MESH (0x0000EA33) chunk starts with standard 12-byte RenderWare framing, followed by the 12-byte stream header:

Offset (Abs) Offset (Rel) Size Type Endian Field Name Description
0x00 - 4 UInt32 LE ChunkType EA Chunk Type 0x0000EA33 (33 EA 00 00).
0x04 - 4 UInt32 LE MeshChunkSize Total chunk payload size: 12 + HeaderDataSize + GpuDataSize.
0x08 - 4 UInt32 LE RenderWareVersion Library ID 0x1C02002D (RenderWare v3.7.0.2).
0x0C 0x00 4 UInt32 LE FormatVersion Format version flag (always 0x00000010).
0x10 0x04 4 UInt32 LE HeaderDataSize Size of Buffer 1 (CPU Metadata) in bytes (previously misnamed FaceDataOff).
0x14 0x08 4 UInt32 LE GpuDataSize Size of Buffer 2 (GPU Vertex & Index Streams) in bytes (previously MeshDataSize).
0x18 0x0C - - - Buffer 1 Base (Metadata) Start of CPU Metadata Buffer (length = HeaderDataSize).
0x18 + HeaderDataSize - - - - Buffer 2 Base (GPU Data) Start of GPU Vertex/Index Buffer (length = GpuDataSize).

Corpus Invariant Formula: Every valid preinstanced mesh satisfies: $$\text{MeshChunkSize} = 12 + \text{HeaderDataSize} + \text{GpuDataSize}$$ Because Buffer 2 begins at 0x18 + HeaderDataSize, adding HeaderDataSize to any Buffer 2-relative offset resolves the absolute file offset of the GPU vertex and face streams.

Relocation Table (mDataTable Decoded)

Located in Buffer 1 starting at offset 0x1C (file 0x34). Declared by RelocCount at Buffer 1 + 0x14 (file 0x2C, previously called TableCount). Each entry is an 8-byte pointer fixup record processed at 0x005549A4 in EBOOT.elf:

Entry Offset Size Type Endian Field Name Description
0x00 4 UInt32 BE TargetOffset Byte offset within Buffer 1 where a 32-bit pointer is stored.
0x04 4 UInt32 BE BufferTarget Relocation destination buffer flag:
• 0: Relocate against Buffer 1 (Metadata)
• 1: Relocate against Buffer 2 (GPU Vertex/Index Data)

Decompiled Disassembly Logic (0x005549CC–0x00554A14):


for (uint32_t i = 0; i < RelocCount; i++) {
    RelocationEntry* entry = &RelocTable[i];
    uint32_t* targetPtr = (uint32_t*)(Buffer1_Base + entry->TargetOffset);
    if (entry->BufferTarget == 0) {
        *targetPtr += (uint32_t)Buffer1_Base; // In-memory metadata pointer fixup
    } else {
        *targetPtr += (uint32_t)Buffer2_Base; // GPU VRAM vertex/index pointer fixup
    }
}

For example, in controller_58afb3.dff.PS3.preinstanced, entry target_offset = 0x01FC fixes up VertexStartRel and target_offset = 0x021C fixes up FaceStartRel with buffer_target = 1.

Sub-Meshes & Vertex Info Structures

The submesh table begins immediately after the relocation table at Buffer 1 + 0x1C + RelocCount * 8. The number of submeshes is declared by SubmeshCount at Buffer 1 + 0x18.

Sub-Mesh Table Entry (12 bytes)

Offset Size Type Endian Field Name Description
0x00 8 Byte[8] - StructuralPrefix Submesh flags / structural marker.
0x08 4 UInt32 BE SubmeshRelOffset Relative byte offset from Buffer 1 base to the Submesh Header.

Pointed-To Submesh Header (16 bytes)

Located at Buffer 1 + SubmeshRelOffset:

Offset Size Type Endian Field Name Description
0x00 4 UInt32 BE Flags Primitive and submesh render flags.
0x04 4 Float32 BE BoundsRadius Submesh bounding sphere radius.
0x08 4 UInt32 BE MaterialId 0-based index into the rwID_MATLIST material array.
0x0C 4 UInt32 BE VertexInfoRelOffset Relative byte offset from Buffer 1 base to the Vertex Info block.

Vertex Information Block

Located at Buffer 1 + VertexInfoRelOffset:

Offset Size Type Endian Field Name Description
0x00 4 UInt32 BE VertexTotalSize Total byte size of vertex buffer for this submesh.
0x04 4 UInt32 BE VertexStride Bytes per vertex record (typically 28, 36, or 40).
0x10 4 UInt32 BE VertexStartRel Offset into Buffer 2 where vertex attribute data begins.
0x28 4 UInt32 BE FaceByteLen Total byte size of triangle strip index buffer.
0x30 4 UInt32 BE FaceStartRel Offset into Buffer 2 where index data begins.

GPU Mesh Data Extraction (Buffer 2)

Vertex Buffer

Absolute File Offset: 0x18 + HeaderDataSize + VertexStartRel

Vertex Count: VertexTotalSize / VertexStride

Offset (Within Stride) Size Type Field Name Description
0x00 12 Float32[3] BE Position (X, Y, Z) 3D vertex coordinates in local model space.
0x0C 4 Byte[4] PackedNormal RSX packed surface normal vector (X, Y, Z signed byte or 10-10-10-2).
0x10 4 Byte[4] PrelitColor Prelit vertex color / RGBA tint and ambient illumination.
0x14 4 Float32 BE UV0_U Primary diffuse texture U coordinate.
0x18 4 Float32 BE UV0_V Primary diffuse texture V coordinate (invert: 1.0 - V).
0x1C 4 Float32 BE UV1_U Secondary / lightmap / toon shadow U coordinate (present when stride >= 36).
0x20 4 Float32 BE UV1_V Secondary / lightmap V coordinate (invert: 1.0 - V).
0x24+ N Bytes AdditionalAttributes Bone weights or additional UV coordinates when stride > 36.

Face / Index Buffer

Absolute File Offset: 0x18 + HeaderDataSize + FaceStartRel

Index Count: FaceByteLen / 2

  • Stored as an array of Big-Endian UInt16 indices.
  • Primitive Restart Value: 0xFFFF (65535) represents a triangle strip cut delimiter. Strips are split at 0xFFFF before triangulation.
  • Triangulation: De-strip with alternating winding parity: 
    
for i in range(len(strip) - 2):
    v1, v2, v3 = strip[i], strip[i + 1], strip[i + 2]
    if v1 == v2 or v1 == v3 or v2 == v3:
        continue # degenerate triangle
    if (i % 2) != 0:
        triangles.append((v1, v3, v2))
    else:
        triangles.append((v1, v2, v3))

Complete Parsing Algorithm (Pseudocode)


function parse_preinstanced_stream(data):
    // 1. Walk RenderWare chunk hierarchy
    clump = read_rw_chunk(data, 0)
    assert clump.type == 0x10 // rwID_CLUMP

    materials = []
    for geom in clump.find_all(0x0F): // rwID_GEOMETRY
        matlist = geom.find(0x08)     // rwID_MATLIST
        for mat in matlist.find_all(0x07): // rwID_MATERIAL
            tex = mat.find(0x06)      // rwID_TEXTURE
            diffuse_name = tex.get_string(0) // First rwID_STRING
            mask_name = tex.get_string(1)    // Second rwID_STRING
            materials.append({
                diffuse: diffuse_name,
                mask: mask_name
            })

    // 2. Locate EA_EARS_MESH (0x0000EA33) chunk
    mesh_chunk = clump.find_extension(0x0000EA33)
    p = mesh_chunk.payload_offset

    format_version   = read_u32_le(data, p + 0x00) // 0x00000010
    header_data_size = read_u32_le(data, p + 0x04) // Size of Buffer 1 (CPU Metadata)
    gpu_data_size    = read_u32_le(data, p + 0x08) // Size of Buffer 2 (GPU Data)

    assert mesh_chunk.size == 12 + header_data_size + gpu_data_size

    buf1_base = p + 0x0C
    buf2_base = buf1_base + header_data_size

    reloc_count   = read_u32_be(data, buf1_base + 0x14)
    submesh_count = read_u32_be(data, buf1_base + 0x18)

    submesh_table_start = buf1_base + 0x1C + reloc_count * 8

    submeshes = []
    for i in range(submesh_count):
        entry_offset = submesh_table_start + i * 12
        submesh_rel = read_u32_be(data, entry_offset + 8)
        submesh_hdr = buf1_base + submesh_rel

        flags = read_u32_be(data, submesh_hdr + 0x00)
        radius = read_f32_be(data, submesh_hdr + 0x04)
        mat_id = read_u32_be(data, submesh_hdr + 0x08)
        vert_info_rel = read_u32_be(data, submesh_hdr + 0x0C)

        vert_info = buf1_base + vert_info_rel
        vert_total_size = read_u32_be(data, vert_info + 0x00)
        vert_stride     = read_u32_be(data, vert_info + 0x04)
        vert_start_rel  = read_u32_be(data, vert_info + 0x10)
        face_byte_len   = read_u32_be(data, vert_info + 0x28)
        face_start_rel  = read_u32_be(data, vert_info + 0x30)

        // GPU Buffers in Buffer 2
        vert_ptr = buf2_base + vert_start_rel
        face_ptr = buf2_base + face_start_rel

        vertices = []
        for v in range(vert_total_size // vert_stride):
            vo = vert_ptr + v * vert_stride
            pos = read_f32x3_be(data, vo + 0x00)
            uv0 = read_f32x2_be(data, vo + 0x14) if vert_stride >= 28 else (0, 0)
            uv1 = read_f32x2_be(data, vo + 0x1C) if vert_stride >= 36 else (0, 0)
            vertices.append({ pos: pos, uv0: (uv0[0], 1.0 - uv0[1]), uv1: (uv1[0], 1.0 - uv1[1]) })

        indices = read_u16_array_be(data, face_ptr, face_byte_len // 2)
        triangles = triangulate_strips_with_restart(indices, restart=0xFFFF)

        submeshes.append({
            material: materials[mat_id].diffuse if mat_id < len(materials) else None,
            vertices: vertices,
            triangles: triangles
        })

    return submeshes

Validation Rules

  • Chunk Size Invariant: For all 0x0000EA33 chunks, MeshChunkSize == 12 + HeaderDataSize + GpuDataSize must hold true exactly.
  • Relocation Table Bounds: All target_offset values in the relocation table must be < HeaderDataSize.
  • GPU Buffer Bounds: VertexStartRel + VertexTotalSize <= GpuDataSize and FaceStartRel + FaceByteLen <= GpuDataSize.
  • Material Bounds: Each submesh MaterialId must be < MaterialCount in rwID_MATLIST.
  • Index Bounds: All non-sentinel vertex indices in the face buffer must be < (VertexTotalSize / VertexStride).
