Maps 32-bit string IDs to one or more columns of localized text or internal labels.

Evidence and limitations

Operation 9 exports table columns without assigning language names. Operation 16 reads the first column of selected global language files directly, so it does not depend on operation 9 CSV output. A language suffix alone does not prove the contents of every table. Runtime fidelity of operation 9 remains to be checked: its binary integer reader uses string.byte, whereas the newer INF/TOX converters use string.unicode and explicitly document the host's high-byte handling. The structural sample checks do not execute that Lua reader.

Operation coverage is grounded in the module manifest and its referenced implementations. Detailed field tables and retained samples below/above are the existing research evidence; labels such as tentative, observed and context must not be read as a complete runtime implementation. Offsets in the added tables are zero-based; range ends are exclusive unless stated otherwise.

LH2 maps 32-bit IDs to columns of strings. The observed PS3 signature is 2HCL, with big-endian integers and absolute offsets measured from the start of the file.

ID array, pointer matrix and strings

The ID array begins at 0x20 and contains N unsigned 32-bit values. The pointer matrix begins at 0x20 + 4*N. Columns are stored consecutively: table 0 has N pointers, then table 1 has N pointers, and so on. Pointer (t,e) is at 0x20 + 4*N + 4*(t*N + e) and points to a NUL-terminated string at an absolute file offset.

Before reading strings, check that 0x20 + 4*N*(1+T) fits inside the file and that every referenced offset and terminator is in bounds. A zero-entry table is distinct from an invalid/truncated header. Shared pointers do not imply duplicate IDs.

Text columns and language variants

The EU flattened inventory contains 654 LH2 files: 554 without a language suffix and 20 each with .en, .es, .fr, .it and .ss. The four language variants supply English, Spanish, French and Italian. The observed global .ss.LH2 table supplies internal labels, not an additional Spanish translation.

Operation 9 writes original.LH2.csv beside the source. It emits an eight-digit hexadecimal String ID and Language 0 onward. For multiple columns it treats the final column as String Label; that is a converter convention, not a guaranteed meaning of every LH2 table. Its reader preserves source characters without an explicit CP1252 control-range remap. Operation 16 explicitly decodes Windows-1252 when producing subtitle text.

Operation 16 selects the first non-empty path-sorted global table for each supported language/label column, reads only its first table, and joins on the numeric ID. It does not merge all duplicate localization copies. The lowercase SDBM label/hash relationship is validated for the TOX dialogue labels described on the timing page; do not generalize that result to every unidentified ID in every format.
