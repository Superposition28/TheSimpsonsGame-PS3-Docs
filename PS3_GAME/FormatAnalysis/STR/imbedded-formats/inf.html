Version: 2.0 (Validated across all 12 PS3 files & 1,784 glyphs)
Last Updated: 2026-10-18
Author(s): yggdrasil-au, samarixum

The .inf format (magic signature FONT, version 6) is Electronic Arts' binary bitmap font descriptor used in The Simpsons Game (PS3) to map characters and controller button prompts onto companion .png texture atlases extracted from RenderWare .txd dictionaries. Each .inf file defines global line metrics, 24-byte per-glyph bounding boxes and typographic bearings, 12.4 fixed-point subpixel atlas coordinates, and a 4-byte kerning pair table.

Endianness: Big-Endian throughout (with 8-bit character IDs padded by a trailing zero byte).
Character Encoding: ASCII (0x20..0x7E), Extended Latin-1 / Windows-1252 hybrid (0xA0..0xFF), and Custom Controller Button Indices (0x00..0x20).
Converter Script: operations/inf_to_fnt.Fonts.lua (exports Godot 4-compatible AngelCode BMFont .fnt descriptors).

How .inf Coincides with .png Font Textures:
  • Shelf Packing Order: Glyphs in the .inf Glyph Table (at offset 0x0434) are sorted in descending order of pixel Height, matching the top-to-bottom, left-to-right shelf packing in the companion .png texture atlas.
  • Pixel Dimensions & Offsets: Each 24-byte glyph record stores integer pixel Width (+0x02), Height (+0x04), horizontal cursor XAdvance (+0x06), signed horizontal bearing XOffset (+0x08), and signed vertical bearing YOffset from the top of the line (+0x0A).
  • 12.4 Fixed-Point Atlas Coordinates: The top-left and bottom-right texture coordinates (X0_Fixed, Y0_Fixed, X1_Fixed, Y1_Fixed at +0x0C..+0x12) are stored in 12.4 fixed-point subpixels (1/16th of a pixel). Shifting right by 4 bits (px = fixed >> 4, or dividing by 16) yields the exact integer pixel coordinates on the .png image. Across all 1,784 glyphs in the game, (X1_Fixed - X0_Fixed) >> 4 == Width and (Y1_Fixed - Y0_Fixed) >> 4 == Height hold with 100% accuracy.
Correction to Legacy v1.0 Notes: Earlier preliminary notes assumed the Glyph Table started at offset 0x78 (120) with 20-byte records. In reality, bytes 0x028..0x428 form a 1024-byte zero-initialized runtime pointer/index buffer, the Kerning Header sits at 0x428..0x434, and the Glyph Table always starts at 0x0434 (1076 decimal, pointed to by header field 0x0C) with 24-byte records. Reading 20-byte structs from 0x78 produced ~48 blank char id=0 entries and unaligned 16×-oversized coordinates that caused Godot 4 to reject the resulting .fnt files with valid=false.

Memory Map & File Layout Overview

Start Offset End Offset Size (Bytes) Section Name Description
0x0000 0x0028 40 (0x28) Main File Header Magic signature ("FONT"), file size, version (6), glyph count, table offsets, and global typographic metrics (MaxGlyphWidth, LineHeight, Baseline).
0x0028 0x0428 1024 (0x400) Runtime Character Index Buffer Zero-filled block (256 × 4 bytes) reserved for in-place runtime fast lookup of 8-bit character codes (0x00..0xFF) after loading into memory.
0x0428 0x0434 12 (0x0C) Kerning Table Header Declares total KerningCount (UInt16 BE at 0x428) and KerningTableOffset (UInt32 BE at 0x42C).
0x0434 LookupTableOffset GlyphCount × 24 Glyph Table Contiguous array of 24-byte glyph descriptors sorted by descending pixel height.
LookupTableOffset LookupTableOffset + 0x404 1028 (0x404) Post-Glyph Runtime Lookup Buffer Zero-filled 1028-byte runtime table immediately following the Glyph Table. If KerningCount == 0, the file ends at LookupTableOffset + 0x404.
KerningTableOffset EOF EOF - KerningTableOffset (observed allocation: KerningCount × 3) Kerning Table 6-byte preamble followed by 4-byte kerning records (FirstChar, SecondChar, Pad=0, Amount). Present only when KerningCount > 0.

Main File Header (0x00 .. 0x28, 40 Bytes)

Offset Size Type Endian Name Description
0x00 4 Char[4] - Magic ASCII signature "FONT" (46 4F 4E 54).
0x04 4 UInt32 BE FileSize Exact total size of the .inf file in bytes.
0x08 2 UInt16 BE Version Format version identifier. Always 0x0006 (6) across all PS3 files.
0x0A 2 UInt16 BE GlyphCount Total number of 24-byte glyph records in the Glyph Table (33, 95, or 191).
0x0C 4 UInt32 BE GlyphTableOffset Absolute byte offset to the start of the Glyph Table. Always 0x00000434 (1076 bytes).
0x10 4 UInt32 BE Flags Reserved / format flags; always 0x00000000.
0x14 4 UInt32 BE MaxGlyphWidth Nominal maximum character width / horizontal advance in pixels (e.g., 25, 20, 45, 51, 28, 76, 102).
0x18 4 UInt32 BE LineHeight Vertical line height in pixels, equal to max(YOffset + Height) across all glyphs (e.g., 33, 41, 54, 56, 57, 68, 97). Maps directly to BMFont common lineHeight.
0x1C 4 UInt32 BE Baseline Distance in pixels from the top of the line to the alphabetic baseline (e.g., 24, 32, 44, 45, 46, 78; 0 for buttons). Maps directly to BMFont common base.
0x20 4 UInt32 BE LookupTableOffset Absolute byte offset to the 1028-byte post-glyph runtime lookup table. Always equals 0x0434 + (GlyphCount × 24) (0x074C, 0x0D1C, or 0x161C).
0x24 4 UInt32 BE Alignment Constant 0x00000004 (4).

Runtime Character Index Buffer & Kerning Header (0x028 .. 0x434, 1036 Bytes)

Offset Size Type Endian Name Description
0x028 1024 UInt32[256] BE RuntimeCharMap All zeros on disk. Populated at runtime to map 8-bit character codes (0x00..0xFF) directly to glyph pointers.
0x428 2 UInt16 BE KerningCount Total number of kerning pairs declared across all glyphs (equals sum(glyph.KerningCount)). Observed values: 0, 77, 272, 281, 377, 411.
0x42A 2 UInt16 BE Padding Always 0x0000.
0x42C 4 UInt32 BE KerningTableOffset Absolute byte offset to the Kerning Table (LookupTableOffset + 0x404: 0x1120 for 95-glyph fonts, 0x1A20 for 191-glyph fonts, or 0x00000000 when KerningCount == 0).
0x430 4 UInt32 BE Padding Always 0x00000000.

Glyph Table (0x0434 .. LookupTableOffset, GlyphCount × 24 Bytes)

Begins at GlyphTableOffset (0x0434). Each glyph is defined by a 24-byte (0x18) structure.

Rel Offset Size Type Endian Name Description
+0x00 1 UInt8 - CharCode 8-bit character ID (or 0..32 button index for buttons.inf).
+0x01 1 UInt8 - CharPad Always 0x00 (allows reading +0x00 as a Little-Endian UInt16 or an 8-bit char followed by 1 byte of padding).
+0x02 2 UInt16 BE Width Bounding box width of the glyph in pixels.
+0x04 2 UInt16 BE Height Bounding box height of the glyph in pixels.
+0x06 2 UInt16 BE XAdvance Horizontal cursor advance in pixels after drawing this glyph.
+0x08 2 Int16 BE XOffset Signed horizontal bearing offset in pixels relative to the current cursor position (can be negative for overhanging glyphs like j or /).
+0x0A 2 Int16 BE YOffset Signed vertical offset in pixels from the top of the line to the top of the glyph bounding box.
+0x0C 2 UInt16 BE X0_Fixed Left texture coordinate in 12.4 fixed-point subpixels. Integer pixel coordinate: X0 = X0_Fixed >> 4.
+0x0E 2 UInt16 BE Y0_Fixed Top texture coordinate in 12.4 fixed-point subpixels. Integer pixel coordinate: Y0 = Y0_Fixed >> 4.
+0x10 2 UInt16 BE X1_Fixed Right texture coordinate in 12.4 fixed-point subpixels. Integer pixel coordinate: X1 = X1_Fixed >> 4 (always equals X0 + Width).
+0x12 2 UInt16 BE Y1_Fixed Bottom texture coordinate in 12.4 fixed-point subpixels. Integer pixel coordinate: Y1 = Y1_Fixed >> 4 (always equals Y0 + Height).
+0x14 2 UInt16 BE KerningCount Number of kerning pairs in the Kerning Table where FirstChar == CharCode.
+0x16 2 UInt16 BE KerningStartIndex 0-based start index into the active kerning pair array (beginning at KerningTableOffset + 6).

Kerning Table (KerningTableOffset .. EOF)

Present when KerningCount > 0 and KerningTableOffset != 0. Begins immediately after the 1028-byte post-glyph runtime lookup buffer (at LookupTableOffset + 0x404).

  • 6-Byte Preamble (KerningTableOffset .. KerningTableOffset + 6): Consists of a 2-byte table flag (01 00 or 00 00) followed by a 4-byte dummy/sentinel kerning entry whose FirstChar is 0x00 (e.g., 00 54 00 FD).
  • Active Kerning Array (KerningTableOffset + 6 .. EOF): Indexed from 0 by each glyph's KerningStartIndex and KerningCount. Each entry is 4 bytes:
Rel Offset Size Type Endian Name Description
+0x00 1 UInt8 - FirstChar Character code of the left/first glyph in the kerning pair (matches the owning glyph's CharCode).
+0x01 1 UInt8 - SecondChar Character code of the right/second glyph in the kerning pair.
+0x02 1 UInt8 - Padding Always 0x00.
+0x03 1 Int8 - Amount Signed 8-bit pixel spacing adjustment applied to the cursor before drawing SecondChar (e.g., 0xFD = -3 px).
EA Offline Font Exporter Truncation Quirk: Across all 8 kerning-enabled .inf files in the PS3 build, the total file size satisfies FileSize == KerningTableOffset + (KerningCount × 3). Because each kerning entry is actually 4 bytes (after the 6-byte preamble), The observed block length is consistent with an exporter allocating KerningCount × 3 bytes when serializing the kerning block, which would truncate the final ~25% of kerning pairs cleanly at EOF. Parsers must stop reading kerning records when offset + 4 > len(data).

Character Sets & Special Glyph Remappings

A. 191-Glyph European UI Fonts (DomCasualStd3636, HighlanderStdBold6060b, HighlanderStdMed3636, LetterGothicStdBold2424b)

Contain 95 printable ASCII characters (0x20..0x7E) plus 96 extended characters (0xA0..0xFF). While most of 0xA0..0xFF follows ISO-8859-1 (Latin-1), 7 byte codes corresponding to rarely used Latin-1 symbols (¬ ± ² ³ ¼ ½ ¾) are repurposed to hold Windows-1252 / MacRoman typographic glyphs required by localized European strings:

B. 95-Glyph Numeric & Title Fonts (simpsons_font, HighlanderStdNumsBold3636b)

  • simpsons_font_acdf54.inf maps all 95 printable ASCII characters (0x20..0x7E) onto a 256×128 atlas.
  • HighlanderStdNumsBold3636b_85009b.inf defines 95 ASCII entries (0x20..0x7E) so the engine's ASCII lookup logic works without bounds checks, but only the first 14 records (/ 4 0 3 2 8 6 9 5 7 1 : , .) have full rendered bitmaps in its 128×128 texture; the remaining 81 non-numeric ASCII characters map to 1×1 transparent pixels along row Y = 109 while retaining valid horizontal XAdvance metrics.

Registered Lua converter and illustrative Python parser

The conversion script at operations/inf_to_fnt.Fonts.lua parses all 12 .inf files, matches them to their .png texture atlases, reads the exact PNG IHDR dimensions, shifts the 12.4 fixed-point UVs into pixel coordinates, and writes valid AngelCode BMFont .fnt files for Godot 4:

From the engine root, run dotnet run -c Debug --project ./EngineNet/ -- --game_module TheSimpsonsGame-PS3 --run_op 15. The Lua entry point accepts --input-dir, --output-dir, --copy-png and --no-unicode-aliases. Output defaults beside each INF, with a relative atlas reference.

The Python fragment below illustrates binary layout only. It is not the registered converter, does not write FNT, and omits several validation/Unicode-alias checks present in the Lua implementation.

import struct
from pathlib import Path

def parse_inf(filepath: Path):
    data = filepath.read_bytes()
    if data[0:4] != b"FONT":
        raise ValueError("Invalid magic signature")

    (
        file_size,
        version,
        glyph_count,
        glyph_table_offset,
        flags,
        max_glyph_width,
        line_height,
        baseline,
        lookup_table_offset,
        alignment,
    ) = struct.unpack(">IHHIIIIIII", data[0x04:0x28])

    kerning_count, _, kerning_table_offset, _ = struct.unpack(">HHII", data[0x428:0x434])

    # 1. Parse 24-byte Glyph Records at glyph_table_offset (0x0434)
    glyphs = []
    offset = glyph_table_offset
    for _ in range(glyph_count):
        char_code = data[offset]
        w, h, xadv, xoff, yoff, x0_fix, y0_fix, x1_fix, y1_fix, kc, ki = struct.unpack(
            ">HHHhhHHHHHH", data[offset + 2 : offset + 24]
        )
        glyphs.append({
            "id": char_code,
            "x": x0_fix >> 4,        # 12.4 fixed-point -> integer pixel X
            "y": y0_fix >> 4,        # 12.4 fixed-point -> integer pixel Y
            "width": w,
            "height": h,
            "xoffset": xoff,
            "yoffset": yoff,
            "xadvance": xadv,
        })
        offset += 24

    # 2. Parse 4-byte Kerning Records at kerning_table_offset + 6
    kernings = []
    if kerning_count > 0 and kerning_table_offset > 0:
        k_off = kerning_table_offset + 6
        while k_off + 4 <= len(data) and len(kernings) < kerning_count:
            c1, c2, pad, amount = struct.unpack(">BBBb", data[k_off : k_off + 4])
            if pad != 0:
                break
            if c1 != 0 and c2 != 0:
                kernings.append({"first": c1, "second": c2, "amount": amount})
            k_off += 4

    return {
        "line_height": line_height,
        "baseline": baseline,
        "glyphs": glyphs,
        "kernings": kernings,
    }
