The .inf format is a custom Electronic Arts / RenderWare binary file used in The Simpsons Game to map characters to a corresponding font texture atlas (usually a .png file). It contains precise coordinate bounding boxes, advancing metrics, and kerning pairs required to render text strings in the game's UI[cite: 8]. These files are typically found embedded within .STR archives alongside their companion textures[cite: 8, 9].

Endianness: Big-Endian throughout.
Character Encoding: ASCII / Custom PUA (Private Use Area) for button icons.

Parsing Algorithm Overview

  1. Verify file starts with the magic signature: 46 4F 4E 54 ("FONT")[cite: 5].
  2. Read the 16-byte header to extract the total file size, format version, total glyph count, and total kerning pair count[cite: 5].
  3. Skip the header padding to reach the start of the Glyph Table (fixed at offset 0x78 or 120 decimal).
  4. Iterate through the specified Glyph Count, parsing 20 bytes per character to extract coordinate boxes (X, Y, Width, Height) and typing offsets[cite: 5].
  5. Starting immediately after the last glyph struct, calculate the remaining file bytes and truncate any trailing garbage padding (dividing by 4).
  6. Parse the 4-byte Kerning structs to extract the spacing modifiers between specific character pairs[cite: 5].
  7. Export the mapped data to an AngelCode .fnt descriptor to bind it to the associated .png texture[cite: 5].

1. File Header

Located at offset 0x00. Size: 16 bytes.

Offset Size Type Endian Name Description
0x00 4 Char[4] - Magic Magic signature: 46 4F 4E 54 ("FONT"). Identifies the file as an EA Font map.
0x04 4 UInt32 BE File Size Total size of the .inf file in bytes.
0x08 2 UInt16 BE Version Format version identifier. Consistently observed as 0x0006.
0x0A 2 UInt16 BE Glyph Count Total number of 20-byte character glyph structs contained in the file.
0x0C 4 UInt32 BE Kerning Count Total number of 4-byte kerning pair structs contained in the file.

2. Glyph Table

Location: Begins at a fixed offset of 0x78 (120 decimal), following the header and a block of padding.
Length: Glyph Count * 20 bytes.

Every character mapped in the font is defined by a 20-byte structure. Note: For generic UI buttons (e.g., buttons_74860e.inf), the character ID may map to non-standard indices.

Offset (Rel) Size Type Endian Name Description
0x00 2 UInt16 BE X Coordinate The X pixel coordinate of the top-left corner of the character on the texture atlas.
0x02 2 UInt16 BE Y Coordinate The Y pixel coordinate of the top-left corner of the character on the texture atlas.
0x04 4 UInt32 BE Padding Empty padding, usually 0x00000000.
0x08 1 UInt8 - Character Code The 8-bit ID mapping this glyph to an ASCII key or controller button.
0x09 1 UInt8 - Padding Empty padding, usually 0x00.
0x0A 2 UInt16 BE Width The width of the character bounding box in pixels.
0x0C 2 UInt16 BE Height The height of the character bounding box in pixels.
0x0E 2 UInt16 BE X-Advance How many pixels horizontally the cursor should advance after drawing this character.
0x10 2 Int16 BE X-Offset A signed value dictating the horizontal drawing offset relative to the cursor (e.g., to handle characters that lean left).
0x12 2 Int16 BE Y-Offset A signed value dictating the vertical drawing offset from the baseline.

3. Kerning Table

Location: Starts immediately after the last byte of the Glyph Table (0x78 + (Glyph Count * 20)).
Length: Kerning Count * 4 bytes.

The kerning table adjusts the spacing between two specific characters when they appear sequentially (e.g., tucking a lowercase 'o' closer under an uppercase 'T').

Offset (Rel) Size Type Endian Name Description
0x00 1 UInt8 - First Char The ID of the first character in the kerning pair.
0x01 1 UInt8 - Second Char The ID of the second character in the kerning pair.
0x02 1 UInt8 - Padding Unused, usually 0x00.
0x03 1 Int8 - Kerning Amount A signed 8-bit integer representing the spacing shift in pixels (e.g., 0xFA = -6 pixels, 0x03 = +3 pixels).

Validation Rules & Padding

  • Files often contain a few bytes of generic trailing padding at the end of the Kerning Table. Safely disregard any remaining bytes that are not perfectly divisible by 4.
  • Button icon atlases (like UI prompts) will map character codes identically, but standard ASCII parsers may read them as unprintable characters unless specifically mapped back to a custom unicode range.

def parse_inf(file_data) {

```
glyph_count = read_u16_be(file_data, 10);

// 2. Parse Glyph Table
offset = 120; // Fixed glyph start
glyphs = [];

for (i = 0 to glyph_count) {
    x = read_u16_be(file_data, offset + 0);
    y = read_u16_be(file_data, offset + 2);
    char_id = file_data[offset + 8];
    width = read_u16_be(file_data, offset + 10);
    height = read_u16_be(file_data, offset + 12);
    xadv = read_u16_be(file_data, offset + 14);
    xoff = read_s16_be(file_data, offset + 16);
    yoff = read_s16_be(file_data, offset + 18);
    
    glyphs.append({char_id, x, y, width, height, xadv, xoff, yoff});
    offset += 20;
}

// 3. Parse Kerning Table
remaining_bytes = len(file_data) - offset;
kerning_count = remaining_bytes // 4; // Truncates trailing garbage
kernings = [];

for (i = 0 to kerning_count) {
    char1 = file_data[offset + 0];
    char2 = file_data[offset + 1];
    amount = read_s8(file_data, offset + 3);
    
    if (char1 != 0 && char2 != 0) {
        kernings.append({char1, char2, amount});
    }
    offset += 4;
}

// 4. Output to AngelCode .fnt mapping format
export_to_fnt(glyphs, kernings);
}
