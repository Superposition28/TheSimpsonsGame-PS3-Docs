RenderWare Texture Dictionary (.txd)

Version: 1.0
Last Updated: 2026-10-02
Author(s): samarixum

The .txd (Texture Dictionary) format used by The Simpsons Game on PS3 has RenderWare chunk framing and a PS3-specific native-texture structure. The file begins with a texture-dictionary chunk, and each native texture is carried in its own chunk. The scanner also uses the texture-record signature and EA extension bytes described below; these byte patterns are not replacements for the enclosing chunk headers.

Endianness: Mixed (see details per section).
Character Encoding: UTF-8 for texture names.

Parsing Algorithm Overview

  1. Read the 12-byte RenderWare chunk header at offset 0x00; its type is 0x16 (Texture Dictionary).
  2. Read the following 0x01 struct chunk and the dictionary count/device fields.
  3. Scan texture records and extension boundaries:
    • Native texture record signature: 2D 00 02 1C 00 00 00 0A
    • Per-texture and dictionary 0x03 extension chunks
  4. Read the texture name from 12 bytes after the record signature.
  5. Check the native metadata block at signature offset +0x50; the parser retains a 01 <format_code> scan as a fallback.
  6. Parse the 16-byte metadata block and the declared base-mip payload.
  7. Unswizzle supported raw formats or pass through supported DXT payloads.
  8. Export to standard image format (DDS)

File Header

Offset Size Type Endian Description
0x00 4 UInt32 LE RenderWare chunk type rwID_TEXDICTIONARY (0x16).
0x04 4 UInt32 LE Chunk payload size, excluding this 12-byte header.
0x08 4 UInt32 LE RenderWare version/build stamp; observed bytes 2D 00 02 1C (0x1C02002D).
0x0C 12 Chunk header Mixed rwID_STRUCT (0x01) chunk header. Its four-byte payload at 0x18 contains the UInt16 texture count followed by the UInt16 device ID.

Segment Markers

Marker (Hex) Purpose Notes
03 00 00 00 14 00 00 00 2D 00 02 1C 2F EA 00 00 08 00 00 00 2D 00 02 1C Per-texture rwID_EXTENSION chunk containing the EA plugin record. The chunk header is type 0x03, size 0x14, version 0x1C02002D. Its payload contains plugin ID 0x0000EA2F, an 8-byte plugin payload, and the plugin version. This terminates a native-texture record; it is not a block-start marker.
2D 00 02 1C 00 00 00 0A Native-texture record marker The bytes contain the RenderWare version stamp and big-endian PS3 platform ID 10. Four filter/address bytes follow; the fixed-width texture-name field begins 12 bytes after this marker.
03 00 00 00 00 00 00 00 2D 00 02 1C Empty dictionary rwID_EXTENSION chunk Type 0x03, payload size 0, followed by the RenderWare version. It closes the outer dictionary; the per-texture extension and this chunk appear adjacent at the end of the file.

Texture Record Structure

Scanning algorithm: Locate the native-texture record marker (2D 00 02 1C 00 00 00 0A). The texture-name field and metadata are at fixed offsets from this marker in the observed PS3 record layout.

Step 1: Texture Name Extraction

  1. Find pattern: 2D 00 02 1C 00 00 00 0A (8 bytes)
  2. Start the name field at marker offset +0x0C: eight signature bytes followed by four filter/address bytes.
  3. Read UTF-8 characters until double null terminator (00 00)
  4. Sanitize string: remove non-alphanumeric chars except ._-
  5. Validate: if empty after sanitization, use fallback name texture_at_0x<OFFSET>

Example: File contains 2D 00 02 1C 00 00 00 0A 00 00 00 00 48 65 6C 6C 6F 00 00.
The four bytes after the marker are filter/address fields; the name begins at marker offset +12 and reads Hello (48 65 6C 6C 6F) before the double-null terminator.

Step 2: Metadata Block Location and Parsing

  1. For the observed PS3 layout, metadata begins at marker offset +0x50. Verify byte +2 is 0x01 and byte +3 is a supported format code.
  2. If that fixed-offset check fails, the current parser scans after the name for 01 <known_format_code>; when found at offset X, it treats X - 2 as the metadata start.
  3. Read exactly 16 bytes starting at the selected metadata offset.

16-Byte Native-Texture Metadata Block

The block begins at record-marker offset +0x50 in the observed PS3 layout. Its fields are mixed-endian: dimensions are big-endian and the base-mip byte count is little-endian. The parser's preamble search remains a compatibility fallback.

Offset Size Type Endian Name Description
0x00 1 UInt8 - Meta0 Leading metadata/descriptor byte; meaning not independently confirmed.
0x01 1 UInt8 - Meta1 Leading metadata/descriptor byte; meaning not independently confirmed.
0x02 1 UInt8 - Preamble_0x01 Must be 0x01. This is the preamble marker we searched for.
0x03 1 UInt8 - Format Code Pixel format identifier. See Format Code Table below.
0x04 2 UInt16 BE Width Image width in pixels. Big-Endian. Validate: > 0.
0x06 2 UInt16 BE Height Image height in pixels. Big-Endian. Validate: > 0.
0x08 1 UInt8 - MetaA Bits per pixel or raster depth in observed records (for example, 32 for 0x86 and 8 for A8 0x02).
0x09 1 UInt8 - Mip Map Count Declared mip-level count. The current exporter only emits the base level and may reduce this count to 1 when the available payload covers only that level.
0x0A 1 UInt8 - MetaB Raster/coordinate type field; exact semantics are not fully confirmed.
0x0B 1 UInt8 - Padding Additional raster flags or padding; exact semantics are not fully confirmed.
0x0C 4 UInt32 LE Initial Mip Size Little-endian byte count for mip level 0 only. The current exporter reads this many bytes after the metadata; it is not the sum of all mip levels.

Validation Rules

  • Width and Height must both be > 0. If both are 0, skip this texture (placeholder).
  • Initial Mip Size must be > 0 and must fit within the remaining segment.
  • Format Code must be supported and must match the preamble when the fallback scan is used.
  • The exporter treats invalid dimensions, sizes, or unsupported formats as an export error. A zero-by-zero record is treated as a placeholder.

Pixel Data Blob

Base mip location: Immediately after the 16-byte metadata block (at offset metadata_block_start + 16).
Base mip length: Initial Mip Size bytes (from metadata). Other readers indicate that later levels may be stored as repeated little-endian UInt32 size prefixes followed by each level's payload. The current C# exporter does not parse or export those later levels.

Format Codes

Format Code (Hex) Format Name Compression Bytes Per Pixel (if uncompressed) Handling
0x52 DXT1 Block-Compressed (4:1 ratio) N/A Copy raw data to DDS with DXT1 FourCC. No further processing.
0x53 DXT3 Block-Compressed (2:1 ratio) N/A Copy raw data to DDS with DXT3 FourCC. No further processing.
0x54 DXT5 Block-Compressed (2:1 ratio) N/A Copy raw data to DDS with DXT5 FourCC. No further processing.
0x86 Swizzled BGRA Uncompressed (Morton-swizzled) 4 Unswizzle using Morton/Z-order decoding. Output is 32-bit BGRA. Export as DDS RGBA8888.
0x02 Swizzled A8 or two-channel L8A8-like data Uncompressed (Morton-swizzled) 1 or 2 Unswizzle. The current converter exports one-byte data as black with alpha and two-byte data as grayscale with alpha; it does not perform palette lookup.

Codes 0x55 and 0x56 have been associated with DXT2 and DXT4 in other parser research, but no such codes were found in the 858 TXD files scanned for this game. They remain unverified and are not accepted by the current converter.

Morton Unswizzling (for Swizzled Formats)

Purpose: PS3 stores textures in Morton/Z-order to improve cache coherency. Data must be reordered to linear memory layout.

Dimension-aware Morton encoding (pseudo-code): Interleave coordinate bits only where that axis has the bit, so rectangular textures use a dense index range rather than unused square-grid positions.


function morton_encode_2d(x, y, width, height) {
    morton = 0
    output_bit = 0
    max_dimension = max(width, height)

    for bit from 0 while (1 << bit) < max_dimension:
        if (1 << bit) < width:
            morton |= ((x >> bit) & 1) << output_bit
            output_bit += 1
        if (1 << bit) < height:
            morton |= ((y >> bit) & 1) << output_bit
            output_bit += 1

    return morton
}

Unswizzling Algorithm:

  1. Allocate output buffer: width * height * bytes_per_pixel
  2. For each y from 0 to (height - 1):
    1. For each x from 0 to (width - 1):
      1. Compute morton_index = morton_encode_2d(x, y, width, height)
      2. Source offset = morton_index * bytes_per_pixel
      3. Dest offset = (y * width + x) * bytes_per_pixel
      4. Copy bytes_per_pixel bytes from source to dest
  3. Return unswizzled buffer

Mipmaps

Current implementation: The size field at metadata offset 0x0C describes the base-mip payload. The C# exporter consumes that payload and does not parse subsequent mip-level size prefixes. Other parser implementations report later levels as repeated little-endian UInt32 size values followed by each level's data; this layout is not currently handled by the C# exporter.

DDS export: When the available payload only covers the base level, the C# converter forces the DDS mip count to 1. It does not claim that unexported mip levels are present.

DDS Export Helper

For DXT Formats (0x52, 0x53, 0x54):

  • Create DDS magic: 44 44 53 20 ("DDS ")
  • Set DDSD_LINEARSIZE flag (for compressed textures)
  • Set FourCC to "DXT1", "DXT3", or "DXT5" accordingly
  • Calculate linear size as max(1, ceil(width/4)) * max(1, ceil(height/4)) * block_size, where block_size is 8 for DXT1 and 16 for DXT3/DXT5.

For RGBA formats (0x86 after unswizzle):

  • Create DDS header for uncompressed RGBA888
  • Set pitch = width * 4
  • No FourCC needed (use pixel format flags)

Complete Parsing Example (Pseudocode)


function parse_txd(file_data) {
    textures = []

    // Validate the texture-dictionary chunk type
    if (read_u32_le(0) != 0x16) return []

    // Scan entire file for texture name signatures
    pos = 0
    while (pos < len(file_data)) {
        if (matches_pattern(file_data, pos, "2D 00 02 1C 00 00 00 0A")) {
            name_signature_offset = pos
            pos += 12  // 8-byte marker and 4 filter/address bytes

            // Read texture name
            name_start = pos
            while (file_data[pos:pos+2] != "00 00") {
                pos += 1
            }
            name = sanitize(file_data[name_start:pos])
            pos += 2  // Skip terminator

            // Prefer the observed fixed metadata offset, then use the fallback scan
            meta_start = name_signature_offset + 0x50
            if not supported_metadata_at(meta_start):
                meta_start = NOT_FOUND

            while (pos < len(file_data) && file_data[pos] == 0x00) {
                pos += 1
            }

            if (meta_start == NOT_FOUND):
                search_pos = pos
                while (search_pos < min(pos + 4096, len(file_data))):
                    if file_data[search_pos] == 0x01 and is_supported_format(file_data[search_pos + 1]):
                        meta_start = search_pos - 2
                        break
                    search_pos += 1

            if (meta_start == NOT_FOUND):
                continue

            // Parse metadata
            metadata = read_metadata_block(file_data, meta_start)
            width = metadata.width
            height = metadata.height
            fmt = metadata.format_code
            base_mip_size = metadata.initial_mip_size

            if (width == 0 || height == 0) continue  // Placeholder

            // Extract pixel data
            pixel_data_start = meta_start + 16
            pixel_data = file_data[pixel_data_start : pixel_data_start + base_mip_size]

            // Unswizzle if needed
            if (fmt == 0x86) {    // Swizzled BGRA
                pixel_data = unswizzle_morton(pixel_data, width, height, 4)
            } else if (fmt == 0x02) {  // Swizzled A8 or two-channel data
                bytes_per_pixel = 1 if base_mip_size < width * height * 2 else 2
                pixel_data = unswizzle_morton(pixel_data, width, height, bytes_per_pixel)
            }
            // For DXT formats (0x52/0x53/0x54), use as-is

            textures.append({
                name: name,
                width: width,
                height: height,
                format: fmt,
                data: pixel_data
            })

            pos = pixel_data_start + base_mip_size
        } else {
            pos += 1
        }
    }

    return textures
}
