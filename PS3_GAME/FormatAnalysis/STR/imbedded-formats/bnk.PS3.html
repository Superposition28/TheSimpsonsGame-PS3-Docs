Game format research · PS3 EU reference baseline

RenderWare CCT character animation bank packaging animation clip names, state machine parameters, keyframe curves, and an in-place pointer relocation table.

Identification
Container header with relocation table offset at 0x00, format version word 0x00000009 (9) at 0x04, bank asset hash at 0x08, target skeleton/model asset hash at 0x0C (joining to .rcb.PS3), clip count at 0x20, and table offset at 0x28 (0x50); verified across all 1,213 files in the PS3 EU extracted corpus.
Byte order / text
Big-endian 32-bit words, IEEE 754 single-precision floats (blend speeds, weights), and null-terminated ASCII animation clip names.
Documentation scope
Format structure and relocation layout verified across all 1,213 extracted .bnk.PS3 files on 2026-11-03. See the evidence section for sample scope; tool support does not establish format completeness.

Format Structure & Breakdown

.bnk.PS3 is a character animation bank compiled by EA's RenderWare CCT pipeline. It packages per-character animation clips, state machine blend parameters, and curve keyframes with an appended pointer relocation table.

Container Header (0x00..0x4F, 80 bytes)

Animation bank container header
Offset Type Field name Description
0x00 uint32 BE RelocationTableOffset Offset to the trailing pointer relocation table; also represents the primary payload size.
0x04 uint32 BE FormatVersion Universally 0x00000009 (9) across all 1,213 verified files.
0x08 uint32 BE BankAssetHash 32-bit unique identifier for the animation bank resource.
0x0C uint32 BE TargetSkeletonHash 32-bit identifier matching the AssetHash at offset 0x08 in the paired .rcb.PS3 rigid body file.
0x20 uint32 BE ClipCount Number of primary animation clips (e.g. 117 for Bart, 141 for Bartman, 2 for weapons/props).
0x24 uint32 BE SecondaryCount Secondary animation channel / track count.
0x28 uint32 BE TableOffset Offset to clip descriptors and index tables (universally 0x50 = 80 bytes).

Pointer Relocation Table

Located at RelocationTableOffset through EOF. Contains an array of 32-bit big-endian offsets in descending order. During loading, the runtime patches every referenced 32-bit word in-place: *(uint32*)(buffer + offset) += (uintptr_t)buffer.

Game Runtime Role

  • Clear animation/state names in the string table:

    • idle_frink, walk_frink, jump_frink, airstate_fall_frink, taunt_frink, plus generic idle, etc.

  • Repeated record blocks pairing a name with ranges/offsets and parameters, with floats like 3F 80 00 00 (= 1.0) typical for blend weights/speeds.

  • Lots of offset tables near the top, then per-clip chunks (start/end pointers like 00 00 01 90 … 00 00 01 A0, etc.)—classic bank layout: header → indices → clip payloads.

  • Small tags like C3, Co, and numeric tuples following entries—these show up in banks as channels/curves (e.g., 3-component transforms, coefficients) and per-clip metadata (rates, durations).

  • Big mid/end blobs of compact numbers/patterns (e.g., long runs of 0x078C, AA/55 bitmasks) typical of compressed keyframes/bit-packed event tracks tuned for SPU/PPU playback on PS3.

What the game uses it for

  • Provides the runtime animations and blend data for Dr. Frink:

    • Base loops (idle_*, walk_*), locomotion variants, air/fall, jump, taunt.

  • Contains transition definitions and blend params the character controller reads to switch states smoothly.

  • Packs curves/events (timings, notifies, maybe footstep markers) in a CPU/SPU-friendly format.

  • Loaded alongside the character’s CCT asset so gameplay code can request “play jump_frink”, “blend to idle_frink”, etc., without touching source .anm/.skel files.
