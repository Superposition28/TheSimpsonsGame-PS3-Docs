Evidence and limitations

The 2026-10-28 original PS3 EU audit validates all 529 ALB occurrences: 519 distinct payloads and 14,283 records after payload deduplication. Every file has size 8 + 24 * EntryCount. Every record joins numerically to SMB stream metadata and LH2 localized text. CTB event selection and original runtime playback remain unresolved. The earlier 28-byte interpretation is superseded; it incorrectly included the next record's first word.

Detailed field tables and retained samples are research evidence. Implementation-derived observations must remain attributed to their tools; tentative, observed and contextual relationships do not establish complete original runtime behavior. Offsets in the added tables are zero-based; range ends are exclusive unless stated otherwise.

Overview

  • Format Name: Audio Library Bank / Alias Bank
  • Common File Extension(s): .alb
  • Purpose/Domain: Metadata layer for managing dialogue streams and other categorized sound events. Defines sound event identifiers (IDs/Hashes) used by the game engine to locate and manage audio playback. Does not contain raw audio data.
  • Originating Application/System: The Simpsons Game (PAL version observed)
  • Format Type: Binary
  • General Structure: Fixed-size Header followed by a variable number of fixed-size Entry Records.

Identification

  • Magic Number(s) / Signature: No traditional magic number, but the first two bytes seem fixed.
    • Value: 0x0006
    • Offset: 0
  • Version Information: Potentially indicated by the first two bytes.
    • Location: Offset 0
    • Data Type: uint16 (Big-Endian)
    • Observed Value: 0x0006

Global properties

  • Endianness: Big-Endian
  • Character Encoding: Not Applicable (Binary format, no significant text strings observed)
  • Default Alignment: Structures appear tightly packed, no explicit padding mentioned beyond potential internal field alignment within the 28-byte record.
  • Compression: None observed.
  • Encryption: None observed.

Detailed Structure

Section: Header

Offset (Hex) Offset (Dec) Size (Bytes) Data Type Endianness Field Name Description Notes / Example Value
0x00 0 2 uint16 Big Format Type/Version Consistently 0x0006. 00 06
0x02 2 2 uint16 Big Entry Record Count Number of Entry Records following the header. 00 0D (13), 00 24 (36)
0x04 4 4 uint32 Big Data Offset Offset to the first Entry Record. Always 8. 00 00 00 08

Section: Entry Records

  • Structure Name: AlbEntry
  • Count: Determined by Header.EntryRecordCount
  • Location: Starts at offset Header.DataOffset (always 8)
  • Total Size per Record: 24 bytes

All offsets below are relative to a 24-byte record. The bank/stream pair and StringID joins are validated throughout the inspected EU corpus; names for the three stream slots remain unresolved. See the worked example and coverage and inline audit scope and worked example.

Offset (Relative) Size (Bytes) Data Type Endianness Field Name Description Notes / Example Value (global_marg.alb)
0x00 4 uint32 Big Alias ID A separate alias identifier; CTB/event selection semantics remain partly unresolved. 11 8B D8 FD, 12 94 15 3E
0x04 4 uint32 Big Bank ID Joins to SMB record +0x04 together with the stream ID at +0x08. It is not a constant flag. A1 B3 C0 62
0x08 4 uint32 Big Sound Hash / Secondary ID 1 Stream ID joining to SMB record +0x08 within the same bank. All three slots are equal in this corpus. 3E 02 F8 57
0x0C 4 uint32 Big Sound Hash / Secondary ID 2 Identical to bytes at offset 0x08. 3E 02 F8 57
0x10 4 uint32 Big Sound Hash / Secondary ID 3 Identical to bytes at offset 0x08. 3E 02 F8 57
0x14 4 uint32 Big LH2 StringID Joins directly to an LH2 ID; that row supplies localized text and an internal line label. B7 14 EE 51, B7 14 EE 52

Data Types Reference

  • uint16: Unsigned 16-bit integer, Big-Endian.
  • uint32: Unsigned 32-bit integer, Big-Endian.

Checksums / Integrity Checks

  • None observed or identified.

Known Variations / Versions

No 28-byte variant or displaced bank-ID field occurred in the inspected EU corpus. The earlier alternate-field hypothesis arose from an incorrect 28-byte stride; +0x18 is the next 24-byte record, not another field. Other platforms/releases still require their own validation.

Analysis Tools & Methods

  • Tools Used: Hex Editor (e.g., HxD, 010 Editor).
  • 2026-10-28 audit: Bounded extraction from all 550 original EU STRs; strict 24-byte ALB records and numeric ALB/SMB/LH2 joins. The worked-example payloads also matched fresh QuickBMS extraction hashes. See the corpus counts, field offsets and remaining gaps.
  • Historical methodology: Manual comparison and analysis of various .alb files using a hex editor. Identifying fixed patterns (header, record size) and variable fields. Correlating repeated values (Sound Hash). Observing differences between files associated with different game contexts (global vs. level-specific).

Open Questions / Uncertainties

  • Precise meaning and usage of Alias ID (Offset 0x00).
  • Original subtitle triggering and display duration; the numeric text association does not establish either.
  • Separate roles of the three equal stream-ID slots at +0x08/+0x0C/+0x10.
  • Exact relationship between Alias ID and the repeated Sound Hash / Secondary ID. Is one derived from the other, or are they independent lookups?
  • Differences in other releases/platforms; this audit covers the inspected PS3 EU source only.
