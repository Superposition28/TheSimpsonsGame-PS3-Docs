Operation pipeline and format coverage

The registered pipeline separates extraction, file organization, conversion and launch configuration. This reference was compared with operations.toml and its Lua/BMS implementations on 2026-10-18. Engine handlers are identified from the manifest; a registered conversion is not evidence that every field or runtime behavior is understood.

Start with the format relationship guide to follow connected assets. Format pages contain byte layouts and file-specific limitations; this page records how the module uses them.

Running an operation

From A:/RemakeEngine/Main, use the module name or module ID 1. Replace 16 with the desired registered operation ID:

dotnet run -c Debug --project ./EngineNet/ -- --game_module TheSimpsonsGame-PS3 --run_op 16

The table lists declared dependencies exactly as stored, not a recommendation to run IDs in numeric order. IDs 7 and 69 are not active operations. Conversion entries have run-all=false; do not assume the menu's run-all selection means every documented format was converted.

Practical input relationships

  • Fonts: operation 15 needs the extracted PNG atlas as well as INF. Operation 3 produces PNGs; operation 6 supplies normalized context. The final dependency chain is not a substitute for checking that the matching atlas exists.
  • Subtitles: operation 16 needs original global LH2 tables and TOX timing files. Operation 9 CSVs are not inputs. Movie pairing works with existing VP6 or OGV, so operation 13 is not a declared prerequisite. Missing translations are omitted from SRT/VTT while timing records remain in CSV.
  • Music: operation 12 declares operation 10 as its dependency, although MUS extraction uses a different input family from SBK decoding. The script chooses an audio root and scans immediate .mus children, not an arbitrary recursive music graph.
  • Models: normalized maps and PNG textures help resolve assets. Geometry conversion does not imply reconstructed physics, animation, effects, object properties or gameplay.

Output naming and retained metadata

Operation 15 keeps the INF stem in the FNT filename and writes a relative atlas reference unless copying is requested. Operation 16 writes timing.tox.PS3.csv plus timing_stem.en.srt/.vtt (and ES/FR/IT equivalents) for non-empty timing tables. For a movie under A1_Video/en/, the paired companion uses the movie's exact stem. A six-hex path suffix is removed for matching, while output filenames retain the original stems.

Operation 16 defaults to writing beside each timing input. --no-video-pairing disables movie companions; selecting --output-dir also suppresses companion writes. --include-speaker adds label-derived speaker text. Empty timing files get CSV only. Missing-language outputs can contain no translated cues; that is not a recovered translation.

Research and platform scope

ALB/CTB, SMB/MIB/MSB, character controllers, Havok resources, BSP/GRAPH, MetaModel, Shock and UIX have research pages but no dedicated registered conversion. Source scripts, editor extensions and illustrative parsers must be identified separately. PS3 and Xbox 360 may share asset concepts while differing in texture tiling, codecs and binary layouts.
