The Simpsons Game (2007) EA .mus Audio Format

File Extension: .mus

Origin: The Simpsons Game (PS3/Xbox 360), EA Redwood Shores.

Purpose: Container archives for interactive, segmented, and layered background music.

1. Verified Facts (What We Know)

  • It is an Archive, Not a Flat Stream: .mus files are not single continuous audio tracks. They are containers holding multiple distinct audio segments (metadata and payload pairs). Treating them as a single raw stream results in completely corrupted static/noise.
  • Big-Endian Table of Contents (TOC): The archive structure relies on a directory/TOC that begins at offset 0x28. The total number of files/segments inside the archive is read as a single byte at offset 0x04 of the header.
  • 28-Byte Structured TOC Entries: Each entry in the TOC is 28 bytes (0x1C) long and contains the following Big-Endian fields (as parsed in mus.bms):
    • 0x00 (uint32): HASH (Sound-specific hash identifier)
    • 0x04 (uint16): NUMBER (Segment stream index/sequence number)
    • 0x06 (uint16): PADDING (Usually always 0)
    • 0x08 (uint32): SNR_OFFSET_RAW (The packed pointer to the SNR header. Multiply by 0x10 to resolve the real file position)
    • 0x0C (uint32): SNS_OFFSET_RAW (The packed pointer to the SNS stream body. Multiply by 0x80 to resolve the real file position)
    • 0x10 (uint32): SNR_SIZE (Exact size of the SNR metadata payload in bytes)
    • 0x14 (uint32): SNS_SIZE (Exact size of the SNS stream payload in bytes)
    • 0x18 (uint32): PADDING (Usually always 0)
  • Interactive Concat/Sequence Mechanics (~2-Second Snippets): The audio tracks are split into consecutively numbered contiguous segments. Each pair represents a very short, approx. 2-second piece of background music (complying with EA's interactive music engine). The full song is constructed by programmatically stitching or playing these segments sequentially one after the other.
  • EA SNR/SNS Container Behavior: The archive holds paired components: the .snr containing stream description metadata (sample rate, channels, EA-XAS ADPCM layout) and the matching blocked .sns containing the audio payload.
  • VGMStream Integration: Running vgmstream directly on the extracted .snr file decodes it cleanly into a standard .wav snippet. It reports the codec as Electronic Arts EA-XAS 4-bit ADPCM v1 using the Electronic Arts SNR+SNS header metadata layout.

2. Background Music Segment Playback & Construction

Because the tracks are split into numerous ~2-second snippets, reconstruction of a full playable soundtrack requires sequencing. The typical workflow used in the mustest.ps1 test script details this behavior:

  1. Unpack the .mus file with operations/mus.bms using QuickBMS to extract all numbered .snr and .sns chunks.
  2. Invoke vgmstream-cli targeting each .snr file individually, exporting them to independent .wav files.
  3. Clean up the intermediate raw .snr and .sns segments, leaving only the converted .wav files.
  4. Stitch the resulting chunks sequentially (e.g., [Filename]__000.wav, then [Filename]__001.wav, and so on) in the engine or media pipeline to reconstruct the full playback.
