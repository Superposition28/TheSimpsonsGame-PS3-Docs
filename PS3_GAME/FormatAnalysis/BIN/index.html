Source scope: PS3 EU Retail full release (BLES00142) is the primary baseline; compared structurally against the PS3 Demo (NPEB90029) and US Retail (BLUS30065). Cross-platform correspondence is established against Xbox 360 default.xex. See roots and provenance.

Game format research · PS3 EU reference baseline

This page documents the PlayStation 3 executable container (USRDIR/EBOOT.BIN) and decrypted ELF binary for The Simpsons Game, covering the outer SCE/SELF wrapper, ELF64/PPC64 section architecture, TOC and procedure descriptor conventions, runtime boot lifecycle, Cell OS PRX imports, embedded SPU programs, Cell GCM RSX push buffer dispatch, and the 21-stage RenderWare frame pipeline.

ELF64 binary layout and TOC architecture

The decrypted executable adheres to the 64-bit PowerPC ELF ABI for Sony PlayStation 3 (Cell OS). Key structural characteristics:

  • Memory Model: 64-bit Big-Endian PowerPC with 32-bit user-space pointers. Code resides in the lower 32-bit address space.
  • TOC Architecture: The primary Table of Contents (TOC) is anchored at 0x00AFDA30, loaded into register r2 across all nominal engine functions. A secondary TOC range (0x00B04660) is utilized by specific RenderWare and graphics backend modules.
  • Official Procedure Descriptors (.opd): PowerPC function pointers do not point directly to executable code bytes; instead, they point to an 8-byte descriptor in .opd consisting of:
    1. Word 0 (4 bytes BE): Virtual address of the target machine instructions.
    2. Word 1 (4 bytes BE): The TOC base address (0x00AFDA30) required by that function.

Startup lifecycle and state machine

The game boot sequence progresses through four verified stages from entry point to interactive gameplay:

  1. ELF Entry Point (0x00014A30): Receives system arguments from the Cell OS kernel and immediately calls CRT startup 0x00010210.
  2. CRT Initialization & Static Constructors: 0x00010210 invokes 0x00014D4C to iterate and execute the table of 26 static constructor descriptors located at 0x00A73E40.
  3. Bootstrap Allocator (0x00014B18): Initializes the global heap allocator singleton (HeapAllocator 0x102E5D68 via Meyers singleton factory 0x0044FE58) before parsing application arguments.
  4. Application Main (0x00054A9C): Loads gameflow definitions from simpsons_gameflow.lua, invokes the actor class registration table at 0x00054BDC, and enters the main loop at 0x005BAA34.

The main loop is driven by a 16-slot application state machine at 0x005B475C (dispatcher at 0x005B443C):

  • 0x00000000 (InitOnce): Initial hardware and gameflow setup; transitions immediately to frontend.
  • 0x2B059711 (FrontendMainLoop): Mounts .str archives, loads localization tables, mounts costumes, and initializes the menu UI.
  • 0xB92397EF (GameMainLoop): Primary in-game simulation loop executing level physics, entity logic, and rendering.

Cell GCM RSX graphics & 21-stage render pipeline

Low-level 3D graphics on PS3 bypasses generic libraries and writes directly into the NVIDIA NV40 / RSX command FIFO:

  • GCM Push Buffer: Managed by Sony's CellGcmContextData struct at global address 0x10380310 (fields begin, end, current, callback).
  • Hardware Command Emitters: Routines 0x00438E3C and 0x0043A2EC write NV406E register packets (0x40194, 0x4018C, 0x801B4, 0x40198) directly into the push buffer.
  • 21-Stage Frame Dispatcher (0x003F6E40): Coordinates camera matrices, stage sorting, and execution. Stage sorting excludes the upper endpoint while execution includes it. Stages 1 and 11 serve as the primary opaque and transparent draw-call submission queues.

Engine actor and RenderWare plugin registries

During application startup, function 0x00054BDC populates the engine's core actor factory by registering 149 named classes through dispatcher 0x003EC9B0:

  • All 149 registrations pass a 32-bit unique ID, printable ASCII name string, 8-byte procedure descriptor (with TOC 0x00AFDA30), and allocation size.
  • Examples: NPCDash (ID 0x5B264B93, size 0x8A0), BartPlayer (ID 0x13B821A4), Door (ID 0x8C1265E0).
  • RenderWare plugin extensions: 0x005540C0 registers clump plugin 0xEA33 (EARS_MESH), reading geometry streams via 0x005542A0 and relocating 8-byte pointer records via 0x005549A4.

Evidence and limitations

The findings documented here are derived from systematic static reverse engineering of Source/PS3/REA/EBOOT.elf (SHA-256 092a8dbf6530e897ab0395ed45b3941e0723b8d50d361b0e958a5a6991d90fbc) using headless Ghidra flow exports, opcode pattern verification, and 135 source-verified function passes. 13,711 instruction records were individually verified against raw ELF bytes with 0 mismatches.

Certain high-level gameplay state triggers, dynamic scripting callbacks, and SPU skinning microcode kernels remain under active investigation.
