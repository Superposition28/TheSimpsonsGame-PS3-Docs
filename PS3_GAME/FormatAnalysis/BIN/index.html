PS3 Executable (EBOOT.BIN / ELF)

Source scope: inspected PS3 EU retail BLES00142, US retail BLUS30065 and EU demo NPEB90029. The supplied EU/US wrappers are byte-identical; demo is a separate executable. These are local-copy observations, not a claim about every published revision or whole-disc equality. Paths below use the original source namespaces.

Game format research · updated 2026-11-03

The executable has an outer SCE/SELF container and an inspected ELF64 big-endian PowerPC payload. This reference records byte layouts and reviewed static code paths. Whole-program reverse engineering remains incomplete.

For a read of n bytes at address v, require one unambiguous PT_LOAD mapping with p_vaddr <= v and v + n <= p_vaddr + p_filesz; then file_offset = p_offset + v - p_vaddr. Validate the resulting file range and arithmetic overflow. Use p_memsz for memory extent only. A zero-fill tail has no corresponding source bytes.

Retail has file-backed VA gaps [0x00A991D0,0x00AA0000) and [0x100AE280,0x100B0000). PH[3] source bytes end at VA 0x10252014, while its memory extent ends at 0x103E58A0. Subtracting a fixed base across those gaps or the zero-fill tail produces false file reads. Low permission bits are R=4, W=2, X=1; preserve the additional raw flag bits without assigning unverified meanings.

Section directory and names

The section-name string table is SH[78] and is entirely zero-filled in both targets. No SHT_SYMTAB or SHT_DYNSYM section is present. Names such as .text, .opd, .toc and .bss in research notes are analyst descriptions, not recovered section-name strings. SHT_NOBITS sections (type 8) declare memory size without file payload. Full section records, including link/info/entry-size fields, are retained in the JSON.

Procedure descriptor candidates and TOCs

SH[22] is the unique writable PROGBITS section containing e_entry. Interpreting it as eight-byte pairs yields a BE32 code address at +0 and BE32 TOC at +4. The entry words and the executable targets of every candidate were checked against source bytes. This supports its descriptor role; its original section name is absent.

Each target has one all-zero slot: retail at 0x00AA8F78, demo at 0x00AA8F80. The retail TOCs differ by 0xFFE0; the demo TOCs differ by 0xFFA0. Track the callee's descriptor and each TOC-adjusting transfer. A primary-TOC assumption for all functions is incorrect. Reviewed indirect descriptor calls load these two 32-bit words even though the PPU registers are 64-bit; this observation does not prescribe the representation of every pointer-like value.

TLS and zero-fill

Retail PH[5] is type 7 (PT_TLS), with an eight-byte initialized template at file 0x00AFFAA0, VA 0x00B0FAA0, and memory size 0x1B4. Demo uses file 0x00AFF858, VA 0x00B0F858, with the same initialized and memory sizes. SH[24] has eight initialized bytes and SH[25] has 0x1AC NOBITS bytes. These describe a template, not a recovered live thread address.

Original ELF32 metadata extraction

Retail 0x9AD644 probes first words JOB1, 0xA122E6A2 and ELF through three helper bodies. These are observed code tests; this pass has no independently inventoried JOB1 or 0xA122E6A2 resource corpus. The JOB1 branch ignores its inner probe's failure result, so matching its outer magic does not establish a valid inner image.

The ELF branch at 0x9AD394 checks the first word for 0x7F454C46 and then reads fixed ELF32 offsets. Its six BE32 result words are: kind 1; the carrier pointer plus the first nonempty PT_LOAD file offset; a file-span accumulator; the ELF32 entry word; selected data pointer; and selected data size. The span adds each nonempty PT_LOAD file size and positive signed32 gaps from the preceding participating segment's file end. It is not a general union-of-ranges size, memory allocation size or declared nested-file extent.

Data selection first seeks a nonempty PT_LOAD with flags exactly 6. If none supplies a data pointer, it walks PROGBITS sections with flags exactly 3, nonzero size and a name equal to the source literal .data. The producer has no explicit buffer-length parameter and does not validate ELF class, byte order, machine, table/name bounds or arithmetic overflow in its body. The bounded inspector's validation is separately implemented; these observations do not define safe input acceptance.

The normal enabled path publishes records through 0x9AB408, converts reference pointers using 0x9AC634, invokes its paired release/notification wrapper and returns 1.   • 0x9AA848 returns 1 iff (record[0x4E] & 0x70) == 0x30, otherwise 0. The reviewed caller polls this predicate; status 0x30 represents task completion.
  • 0x9AA5BC leaves flags old & 0x0F, writes byte+0x14=1, clears the slot-pointer/sequence fields and copies byte+0xB7 to +0x4F.
  • 0x9AA5F8 waits for the same masked status 0x30, issuing literal syscall selector 0x2B between reads, after a sequence of self-register operations. It has no local timeout or error branch. The actual status producer and syscall semantics remain separate evidence.
  • 0x9AB408 writes flags (old & 0x0F) | 0x10 | ((BE32[record]==0) << 7), stores the current sequence and slot back-pointer, then copies record+0x4C/+0x50 to that slot. All 256 flag values were checked using the actual rotate/mask instruction operands.
  • 0x9AB4E4 scans 127 candidate slots in opposite directions for categories 1 and 0, skipping occupied status-2 entries and occupied entries of the requested category. 0x9AB744 can move an occupied candidate into an empty second slot through 0x9AB660; the latter updates its back-pointer and dependent indices. None of these bodies validates arbitrary slot indices or pointers.
  • 0x9AC634 computes the low32 arithmetic-right-shift result of (record.slot_pointer - (context+8)) >> 3. It roundtrips all 127 valid slot pointers; it does not validate an arbitrary pointer.
  • 0x9ACF24 polls the event queue via syscall 0x83, acquires mutex 0x9AC6D0, scans 127 slots for flag bit 2 set, status 0x10 (QUEUED), nonzero payload pointer via 0x9AB198, and dependency count zero (slot+3 == 0). On match, it transitions slot status to 0x20 (RUNNING), releases the mutex, and dispatches via 0x9ACEA0. On exhaustion, it blocks on the event queue via syscall 0x82.
  • 0x9ACEA0 dispatches the task's procedure descriptor (OPD) via bctrl with arguments (context+4, record+0x1C, record+0x10 & 0xFFFFFF) and tail-branches to completion 0x9ACC00.
  • 0x9ACC00 transitions slot status to 0x30 (COMPLETED), decrements dependent task prerequisite counters in record+0x20+4*i, wakes worker threads via syscall 0x8A on port context+0x5C4 when tasks unblock, detaches the record, and marks record+0x4E as status 0x30.
  • 0x9AC3FC orchestrates queue and SPU thread group teardown: joins the SPU group (syscall 0xB2), disconnects SPU events (syscall 0xC0), destroys the SPU group (syscall 0xAB), closes the SPU image (0xA73F8C), frees IDs via 0x9AB13C, and destroys IPC events.
  • 0x9AB044, 0x9AB0B4 and 0x9AB13C implement once-guarded numeric ID pool allocation using a 7-byte bitmap at 0x103A6200.

The release/notification wrapper 0x9AABB0 copies the context's first eight bytes, calls 0x9AC9D0 to clear selected live mask bits/count, calls two import wrappers, then calls 0x9AC76C with the snapshot. The latter preserves the copied mask, decrements its count byte and issues literal syscall 0xB8 for selected entries. Selection uses MSB-first bits, a seven-position lookahead and an inclusive limit. Sentinel index 32 stops only when the configured limit is below 32; those bounds are not enforced locally. Syscall semantics, receiver consumption, valid configuration producers and complete SPU/PPU execution protocols remain unresolved.

Bank trimming and lifetime limits

Cleanup 0x4397BC visits indices 1 through count-1, invoking cleanup calls and clearing the first word for each record whose first word is nonzero; record 0 is preserved. It then writes count=1, even for an incoming count of 0, and leaves selected pointer+0x114 unchanged. Variants 0x439D34/0x439E34 perform the same trimming before another helper call. The found direct trim path is 0x4E320:0x4E954 → 0x436270 → 0x4397BC. The caller places it between calls to 0x32BEEC and 0x490848; a per-frame reset is not established.

Flush 0x439F34 clears pending byte+0x119 without clearing count+0x110 or selected pointer+0x114. Two initialized records, a trim-to-one helper and FIFO dispatch do not establish a safe two-record runtime bound or double buffering. Named registrations and format callbacks

Cross-release and Xbox comparison limits

The supplied retail EU/US wrappers are identical. Demo differs in code/data addresses, descriptor TOCs, import membership and section extents. Matching startup-array counts and byte-equal nested images do not imply identical whole-program behavior. A single global retail-to-demo address delta is invalid.

Xbox 360 default.xex is a separate container and address space. Shared registration tuples and string-signature matches are research anchors. The existing 598 cross-platform correlations include heuristic candidates; they are not 598 semantic function reviews or proof of whole-engine equivalence.
