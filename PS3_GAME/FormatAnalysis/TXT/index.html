Locale configuration (localetable.txt)

Usable text source · five PS3 / Xbox 360 samples · 2026-10-18

The line-based text/localetable.txt file describes locale entries for a particular build. Five supplied copies cover PS3 EU, PS3 demo, PS3 US, Xbox 360 EU and Xbox 360 US. Their locale lists and header tokens differ. The file is separate from binary LH2 string tables and locale-reference text files extracted from STR archives.

Identification
Plain text: five header lines, then five lines per locale record. The leading value 5 is not a reliable record count.
Byte order / text
ASCII with LF line endings; numeric values are decimal text, so binary endianness does not apply.
Scope
All five supplied text files compared; PS3 title IDs cross-checked with adjacent PARAM.SFO metadata. Earlier PS3 EU locale-reference/LH2 checks are retained with their original scope. No executable parser analysis.

All five files contain only ASCII bytes and are also valid UTF-8, with no BOM, CR or NUL bytes. Each ends with two LF bytes: the final record terminator followed by one empty trailing line. The five-record files have 30 non-empty lines and 31 LF terminators; two-record files have 15 non-empty lines and 16 LF terminators.

Paths identify the exact supplied copies. In particular, the Xbox 360 EU copy is the supplied TSG tree; its contents must not be generalized to every European Xbox 360 release. Source paths are descriptive rather than links into proprietary files.

Header and locale records

Five-line header; line numbers are one-based
Line Value Interpretation
1 5 Unresolved header marker, invariant across all five samples. It coincides with the five EU records but remains 5 in the three files with only two records; it cannot be treated as a reliable entry count.
2 BLES00142 Matches TITLE_ID in the adjacent PS3_GAME/PARAM.SFO.
3 pal_en Build/locale token also observed in extracted asset paths; precise loader meaning unverified.
4 0 Unresolved header integer: 1 in the supplied Xbox 360 EU copy; 0 in the other four samples.
5 1 Unresolved header integer: 1 in PS3 EU and PS3 demo; 0 in PS3 US and both Xbox 360 samples.

Records start at line 6 and consume five lines each. In these five samples, RecordCount = (NonEmptyLineCount - 5) / 5, yielding five or two records. This count is derived from the observed layout, not the leading 5. The following table is the PS3 EU reference; field names are descriptive, not recovered variable names.

Locale records in original order
Lines Field 1: locale key Field 2: associated code Field 3: label Field 4: integer Field 5: tag
6–10 en en English 1 (none)
11–15 fr fr French 0 FR
16–20 it it Italian 0 IT
21–25 es es Spanish 0 ES
26–30 ss en StringIDs 0 (none)

In the PS3 EU sample, only English has record field 4 set to 1. The supplied Xbox 360 EU copy also sets this field to 1 for Dansk, Norsk and Suomi, so a unique default-language interpretation is not supported across the sample set. Associated code en appears for those entries and for ss; alias, fallback or shared-resource behavior is plausible but not runtime-verified. The final tag is a literal string such as FR or (none), not an absent line.

Preserve five-line record boundaries, literal markers and record order. Read the five-line header separately, derive the observed record count from complete records, and retain unresolved values. Do not use the leading 5 to read past EOF in a two-record variant, remove a StringIDs entry as if it were a blank record, or assume one record flag uniquely selects a default language. Blank-line handling by the original game parser remains unverified.

Leading marker: every file starts with 5, regardless of whether two or five records follow. A version/type marker is a possibility; its actual meaning remains unknown. This comparison supersedes the earlier single-sample count interpretation.

PS3 demo versus PS3 US: both are 73 bytes and contain the same identifier, build token and EN/SS records. They differ at exactly one byte: file offset 0x16 (22 decimal), where header line 5 is ASCII 1 in the demo and 0 in the US copy. That observation alone does not establish a demo flag: the full PS3 EU copy also uses 1.

Demo identity mismatch: the demo table stores BLUS30065, while its adjacent PARAM.SFO identifies NPEB90029 and The Simpsons™ Game Demo. The PS3 EU and US table identifiers match their adjacent PARAM.SFO title IDs. Treat the demo table identifier as a stored token, not authoritative proof of the installed package's identity. A reused configuration is a possible explanation, not an established build history.

Supplied Xbox 360 EU copy: the records are English, Dansk, Norsk, Suomi and StringIDs, not the English/French/Italian/Spanish set in the PS3 EU copy. Every associated code is en, and every tag is (none). The four named-language entries have record integer 1. These bytes do not by themselves demonstrate separate Danish, Norwegian or Finnish translation or audio assets.

US comparison: PS3 US and Xbox 360 US have identical header values other than the line 2 identifier, and identical EN/SS record blocks. Xbox identifiers EA205702E0X11 and EA205701A0X11 are preserved as observed tokens; their internal structure has not been decoded.

Localization relationships

All five copies retain ss / en / StringIDs / 0 / (none). This label distinguishes the internal entry from named-language entries, even in the two-record variants. In the previously inspected PS3 EU dataset, global LH2 tables corroborate this: EN/FR/IT/ES contain readable localized text; SS contains internal labels such as CREDITS_IntEngineers_1. This locale configuration contains no translated strings, per-string IDs, subtitle timings or font selection.

The two previously inspected PS3 EU localereftableD4815ED6_*.txt files under extracted frontend and character archives list the PS3 EU locale keys and these resource IDs. This resource mapping has not been re-established for the other four variants:

In every row of both reference tables, signed_decimal & 0xFFFFFFFF == hexadecimal_ID. These are two representations of the same 32-bit ID, not evidence of a separate content checksum. The PS3 EU reference tables start with 2; their layout is distinct from the five-line-header locale configuration family documented here.

Matching ID-named localization directories and global LH2 suffixes support the locale/resource association. Lookup order and fallback behavior remain unverified. Resource paths and IDs belong to the separate reference tables; localetable.txt itself does not store them.

Related formats

Embedded text resources (.txt) describes the separate locale-reference family. Its historical checksum/loader hypotheses should be read alongside the direct signed-ID comparison above. The format relationship guide explains localization, movie timing and font rendering.

PARAM.SFO metadata compares the authoritative PS3 title IDs with the locale-table identifiers, including the demo mismatch, and documents the separate binary metadata layout.

Operation support

The file is readable directly; no conversion is required for inspection and no dedicated locale-configuration parser is registered in operations.toml. This source-disc file is not a payload produced by STR extraction. Operations 9 and 16 read LH2 resources, not this configuration. See the operation pipeline for their actual inputs.

Evidence and limitations

All five supplied locale tables were read directly on 2026-10-18. Sizes, SHA-256 values, ASCII/LF encoding, five-line headers, complete five-line record groups and trailing blank lines were checked. The three PS3 table identifiers were compared with adjacent PARAM.SFO metadata; demo/US byte differences and shared record blocks were compared exactly. Xbox package identifiers were not cross-validated against an independent metadata source. Earlier signed-ID and LH2 checks apply to PS3 EU only.

The invariant leading marker, header integers, record integer, associated-code behavior, tags and original runtime loading rules remain unresolved. Locale labels and path names do not prove that translated assets exist or that every release in a region uses the same table. No executable analysis was performed; the comparisons are limited to these five copies.
