Remake Engine operation pipeline

This is optional project integration documentation. For the game itself, start with canonical sources, file formats and asset/use analysis.

The registered pipeline separates extraction, file organization, conversion and launch configuration. This reference was compared with operations.toml and its Lua/BMS implementations on 2026-10-28. Engine handlers are identified from the manifest; a registered conversion is not evidence that every field or runtime behavior is understood.

Start with the format relationship guide to follow connected assets. Format pages contain byte layouts and file-specific limitations; this page records how the module uses them.

Running an operation

From A:/RemakeEngine/Main, use the module name or module ID 1. Replace 10 with the desired registered operation ID:

dotnet run -c Debug --project ./EngineNet/ -- --game_module TheSimpsonsGame-PS3 --run_op 10

The table lists declared dependencies exactly as stored, not a recommendation to run IDs in numeric order. The commented Godot generation entry (69) is not active. Current conversion entries generally have run-all=true; the isolated local variant (18) and reset (6677) remain opt-in. Registration and run-all flags do not prove a completed conversion run.

STR categorized-output contract (2026-10-28)

The STR investigation distinguishes unnamed SimGroup records from assets with an empty pathname. operations/simpsons_str.bms now uses the 12-byte outer envelope and little-endian body size to walk every record. It preserves exact payload bytes and assigns category suffixes to identified DAT families. Named UIE paths ending in .dat gain .uie; other named asset paths remain as stored. It assigns the following synthetic names inside each archive's output directory. The section index and record offset are zero-based; the offset is relative to the decompressed section, not the source file.

  • simgroup_sNNN_oXXXXXXXX.dat.simgroup: complete 0x2207 body when SimG occurs at body +8. For US loc/loc/zone06.str, simgroup_s003_o00000660.dat.simgroup contains 244 bytes; the old numeric DAT omitted four bytes and contained 240.
  • uie_sNNN_oXXXXXXXX.dat.uie: exact payload of an empty-path 0x1607 asset with metadata type UIE. Unidentified empty-path asset families retain unnamed_asset_sNNN_oXXXXXXXX.dat. A named UIE ui.dat becomes ui.dat.uie; the final .dat check is case-insensitive, and already categorized names are not suffixed twice.
  • chunk_TTTT_sNNN_oXXXXXXXX.dat: complete opaque body for an unparsed outer type, an unrecognized SimGroup signature, or a zero-header asset. The outer type is retained in the name; its payload family is unidentified, so it receives no guessed category. SimG-like bytes in an unknown outer type are insufficient for the SimGroup category. Bodies are not combined with later records.
  • __str_duplicates__/sNNN_oXXXXXXXX/<embedded-path>: later assets with a repeated pathname (case-insensitive comparison). The first output keeps its embedded path. Drive colons in the duplicate path become underscores. In the US story sample, the second StreamSetConfig is preserved at __str_duplicates__/s010_o0003e958/StreamSetConfig.

Only identified SimGroup and UIE DAT families receive the current .simgroup/.uie category suffixes. Plain .dat is reserved for payload families without an established identification in the extractor. A metadata type name alone does not justify inventing a category for an undocumented family. Categorization occurs before case-insensitive duplicate-path detection; later duplicates keep the category beneath __str_duplicates__/.

These names identify extractor output and do not claim recovered original filenames. Full SimGroup bodies use the pointer base expected by the inspected C# viewer; old numeric DATs need the documented four-byte base correction. Unknown bodies remain opaque. Boundary/header mismatches print ERROR: and terminate the script; QuickBMS CleanExit does not guarantee a nonzero process exit code.

For a manual run from the game-module root, select one source archive and a separate output directory per archive:

& 'A:\RemakeEngine\Main\EngineApps\Tools\QuickBMS-0.12.0-win-x64\quickbms_4gb_files.exe' -o `
  'operations\simpsons_str.bms' `
  'Source\PS3\US\1\PS3_GAME\USRDIR\loc\loc\zone06.str' `
  'reversing\TMP_STR\loc-zone06'

Use a fresh output directory when migrating numeric DATs or the earlier unsuffixed simgroup_s*.dat/uie_s*.dat outputs: -o overwrites matching paths but does not remove obsolete names. Existing extracted trees are not renamed by changing the script. Reruns into the same updated destination were verified to retain identical names and hashes. QuickBMS -K or rename-on-collision choices can still create extra files.

python -B reversing/str_audit.py <STR-file-or-root> <report.json> in the parent module independently decodes RefPack, validates record boundaries and records source/body/payload SHA-256 values. It does not extract assets. The audit was validated against all 490 inspected US STRs. python -B reversing/test_str_extraction.py --quickbms <exe> --scratch <directory> exercises generated raw/compressed archives, later records, unknown types, empty paths, repeated paths, malformed boundaries and stable reruns without game data. The nine cases include raw/compressed SimGroup categories, empty/named UIE DATs, unknown-type signature lookalikes and final-name collisions. All cases passed on both QuickBMS 0.12.0 builds. Fresh original EU loc/loc.str and loc/loc/zone06.str extractions also matched independent source-body/payload hashes for their three categorized outputs. The original archive hashes remained unchanged. The inline STR investigation retains real-sample coordinates and extraction comparisons. The former separate JSON ledger is not distributed here.

Practical input relationships

  • Fonts: operation 9 needs the extracted PNG atlas as well as INF. Operation 5 produces PNGs; operation 6 supplies normalized context. The final dependency chain is not a substitute for checking that the matching atlas exists.
  • Subtitles: operation 10 needs original global LH2 tables and TOX timing files. Operation 8 CSVs are not inputs. Movie pairing works with existing VP6 or OGV, so operation 14 is not a declared prerequisite. Missing translations are omitted from SRT/VTT while timing records remain in CSV.
  • Music: operation 13 declares dependencies [-1, 2, 6] for tools, staged source media and normalized context; MUS extraction uses a different input family from SBK decoding. The script chooses an audio root and scans immediate .mus children, not an arbitrary recursive music graph.
  • Models: normalized maps and PNG textures help resolve assets. Geometry conversion does not imply reconstructed physics, animation, effects, object properties or gameplay.

Output naming and retained metadata

Operation 9 keeps the INF stem in the FNT filename and writes a relative atlas reference unless copying is requested. Operation 10 writes timing.tox.PS3.csv plus timing_stem.en.srt/.vtt (and ES/FR/IT equivalents) for non-empty timing tables. For a movie under A1_Video/en/, the paired companion uses the movie's exact stem. A six-hex path suffix is removed for matching, while output filenames retain the original stems.

Operation 10 defaults to writing beside each timing input. --no-video-pairing disables movie companions; selecting --output-dir also suppresses companion writes. --include-speaker adds label-derived speaker text. Empty timing files get CSV only. Missing-language outputs can contain no translated cues; that is not a recovered translation.

Research and platform scope

The standalone original-source dialogue audit reads ALB/SMB/LH2 and produces subtitle test videos; it is separate from registered operations. CTB event logic, MIB/MSB playback, character controllers, Havok resources, BSP/GRAPH, MetaModel, Shock and UIX need their own parsers and runtime semantics. Existing editor/test support is documented separately from registered conversion coverage. Source scripts, editor extensions and illustrative parsers must be identified separately. PS3 and Xbox 360 may share asset concepts while differing in texture tiling, codecs and binary layouts.
