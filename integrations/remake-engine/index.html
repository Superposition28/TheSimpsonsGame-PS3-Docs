Extraction and normalization conventions

Full is the documentation's canonical extracted view. FullFlattened is an alternate view produced by additional directory normalization. Base-folder renaming and audio reorganization already occur before flattening. The normalizer's original_path refers to Full, not the disc. Preserve original archive/member identity separately when available.

Flattening can remove build/platform segments, collapse directories, rename texture_dictionary, and append six-hex path-derived suffixes. These suffixes are processing identifiers, not automatically embedded game IDs. The local normalizer JSON maps connect the two extracted views.

AudioMap consumer contract

The maintained registry is PS3_GAME/USRDIR/A1_Audio/AudioMap.yaml, now using schema_version: 2. Its JSON Schema defines locations, speakers and assets. The earlier V1 research snapshot is historical data; the current consumer requires V2.

Operation 4 runs operations/Audio/SetupAudioDir.lua with --execute. It accepts a generated dataset root or its A1_Audio/audiostreams folder. Its first filesystem phase moves loose English bank directories into EN and mapped global banks into Global, merging existing banks without overwriting files. Unrecognized English bank contents remain beneath EN for later review. Standalone MUS archives and the generated root Music directory remain in place. Direct script calls default to a dry run, which leaves the audio tree unchanged.

Source scope selects EN/ES/FR/IT or Global. Original directories, explicitly recorded legacy directory aliases and filename patterns identify streams; ####### matches exactly seven hexadecimal characters. Dialogue routes through Dialogue, speaker type and stable speaker ID, or an explicit character/variant relationship. Non-dialogue assets route through Cutscenes, Ambience, SoundEffects, Music or Unmapped, with a single known location, MultipleLocations or UnresolvedLocation. Unknown identities and usage remain explicit. Standalone MUS archives and other non-EXA.SNU files stay in place.

The consumer validates registry references and patterns, compiles filename lookup tables once and scans file metadata once. Bank and current V2 path matches take precedence; a unique complete filename-pattern match within its language/global scope also recovers streams in unrecorded older folders. Unmatched or ambiguous EXA.SNU files, collisions, linked entries and failed moves are retained and reported while independent streams continue. Only directories explicitly checked as empty are removed, including emptied banks under other language folders.

Normal sorting uses same-volume, no-overwrite moves through the Lua SDK. Script and console progress bars cover registry loading, bank staging, discovery, sorting and cleanup. Retained-file warnings and a concise completion summary appear in the console. The operation creates no JSON reports, timing reports, execution plans or per-file journals. Runtime writes are restricted to GameFiles; Source is rejected as a target.

The entry script coordinates focused Lua modules in operations/Audio/: AudioMap validates the registry, AudioRouting resolves destinations, AudioFiles reorganizes files, AudioPaths enforces target restrictions using shared path helpers, and AudioProgress handles live feedback.

Rerunning recognizes already sorted files, retries retained files and uses the current YAML without requiring the old plans or journals. A dataset renamed by pipeline success hooks is also recognized from its contents. A forced process termination leaves a sibling .v2-execute.lock; remove it only after confirming that process has stopped. V2 retains all 242 V1 filename mappings: 144 dialogue, 34 cutscene and 64 global entries. These output conventions describe consumer behavior; character, level and stream associations remain research data, and output paths do not prove original paths or runtime event mappings.
