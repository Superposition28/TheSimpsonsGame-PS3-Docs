Extraction and normalization conventions

Full is the documentation's canonical extracted view. FullFlattened is an alternate view produced by additional directory normalization. Base-folder renaming and audio reorganization already occur before flattening. The normalizer's original_path refers to Full, not the disc. Preserve original archive/member identity separately when available.

Flattening can remove build/platform segments, collapse directories, rename texture_dictionary, and append six-hex path-derived suffixes. These suffixes are processing identifiers, not automatically embedded game IDs. The local normalizer JSON maps connect the two extracted views.

AudioMap consumer contract

The maintained registry is PS3_GAME/USRDIR/A1_Audio/AudioMap.yaml, now using schema_version: 2. Its JSON Schema defines locations, speakers and assets. The earlier V1 research snapshot is historical data; the current consumer requires V2.

Operation 4 runs SetupAudioDir.lua with --execute. It accepts a generated dataset root or its A1_Audio/audiostreams folder, detects raw, earlier sorted and V2 paths, and preserves original filenames. Direct script calls default to a dry run. Runtime planning and execution use the engine's Lua SDK; Python is only needed for the independent authoring validator and regression tests.

Source scope selects EN/ES/FR/IT or Global. Original directories, explicitly recorded legacy directory aliases and filename patterns identify streams; ####### matches exactly seven hexadecimal characters. Dialogue routes through Dialogue, speaker type and stable speaker ID, or an explicit character/variant relationship. Non-dialogue assets route through Cutscenes, Ambience, SoundEffects, Music or Unmapped, with a single known location, MultipleLocations or UnresolvedLocation. Unknown identities and usage remain explicit. Standalone MUS archives and other non-EXA.SNU files stay in place.

Before moving audio, the consumer validates references, paths and overlapping patterns and inventories every file. Unmatched or ambiguous EXA.SNU files, links, collisions and changed files stop execution. Immutable plans and per-file intent/verification records live under GameFiles/config/audio-v2/<audio-root-hash>/. Copies are verified with the engine's SHA-1 file hash before originals are removed; the Python validator can independently inventory SHA-256. Interrupted copies resume against the same plan. The final report records moved, already sorted and unmanaged files. An abrupt process termination leaves a sibling .v2-execute.lock; remove it only after confirming that process has stopped.

Changing the YAML invalidates an existing plan. Regenerate the disposable audio dataset and remove its corresponding audit directory before preparing a new mapping. A dataset root renamed by pipeline success hooks gets a new audit identity and is recognized as already sorted. These output conventions describe consumer behavior; character, level and stream associations remain research data, and output paths do not prove original paths or runtime event mappings.

Implementation evidence

Source-inspected parsers are evidence of what a tool reads. Converter fallbacks, discarded fields, generated outputs and editor resource classes must remain attributed to that tool. They are not recovered original-game behavior.
